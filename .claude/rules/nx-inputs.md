# nx の inputs を足す前に

test / lint のレーン（`test-*` / `lint-*` target）は `cache: true` で、inputs が変わらない限り
前回の結果を再利用します (#1225)。inputs に書いたファイルは、そのファイルの変更でこのレーンを
実行させる宣言にもなります。projectRoot（プラグイン）の外を書くと、その外側の変更でも project ごと
affected になります。

## 「テストが読む」だけでは inputs に足さない

inputs に入れるのは、変わったときにこの target の判定が変わり、しかもほかのどのレーンも
その変化を確認していないファイルだけです。strace などで「読んでいる」と分かったファイルを
そのまま全部足すと、無関係な変更のたびに重いレーンが実行されます。

足す前に、次を確かめます。

- そのファイルは、この target が確認する対象か。テストの材料として借りているだけか
- そのファイルの変更を確認するレーンが、ほかにあるか
- glob が何ファイルに当たり、どんな日常の変更（レイアウトの追加、文言の微調整など）で
  このレーンを起動することになるか

材料として借りているだけで、持ち主のレーンが確認しているなら、足しません。代わりに、
足さない理由を target の metadata か `//inputs-reason` に書きます。

## 例: pecot-visual の test-cli とテーマの素材

test-cli の e2e は、`slide create` などの動作確認に、
`cli/tests/fixtures/themes/` 配下の fixture テーマを使います。
fixture テーマの中身を確認するためではありません。
本体はテーマを持たず、テーマの中身はテーマ側のリポジトリが確かめます。

そのため fixture テーマは、テストが実際に読むファイルだけを inputs に入れます。
丸ごと入れると、日常の変更のたびに約 75 秒の cli のテストが実行されます。
