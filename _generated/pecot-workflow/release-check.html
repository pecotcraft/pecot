release check

release check

リリースの前の確認をします。nx のリポジトリでは、alert だけを確かめます。

リポジトリの open の Dependabot・code scanning・secret scanning の alert を確かめます。

3 種類は、先の確認が失敗しても、必ずすべて確かめます。

open の Dependabot alert は warning として扱い、コマンドは止まりません。

Dependabot の warning には、alert ごとの #<number>・パッケージ・severity と、alert のページの URL を並べます。

open の code scanning alert か secret scanning alert があると、コマンドは失敗します。

機能が無効のリポジトリは、skipped の行を出して通ります。

権限が無いなどで code scanning か secret scanning の状態を判定できないと、コマンドは失敗します。

リリースの種類が nx のリポジトリでは、alert だけを確かめます。版の引数と --package は受け付けません。

それ以外では、次のことを確かめます。CHANGELOG があること。版が X.Y.Z の形であること。タグがローカルとリモートのどちらにも無いこと。<develop_branch> に、<release_branch> に無いコミットがあること。タグの確認に使う <remote> は origin で、origin が無ければ最初の remote です。

版の引数が無いときの版は、CHANGELOG の最初の ## [X.Y.Z] の見出しです。Unreleased の見出しは飛ばします。

CHANGELOG は、設定ファイルにあるリポジトリの changelog_file です。

changelog_file が無いときの CHANGELOG は、git のルートの CHANGELOG.md で、その次が AIST-CHANGELOG.md です。--package を付けたときは、そのパッケージの changelog です。

タグは v<version> です。

--package を付けると、タグは <package>-v<version> です。

packages を設定したリポジトリでは、--package が必須です。

packages の無いリポジトリでは、--package を受け付けません。

リポジトリは、pecot 全体のオプション --repo から決めます。無ければ remote の origin から、origin も無ければ最初の remote から決めます。

--repo が git remote と違っても、git のコマンドは origin を使います。origin が無ければ、最初の remote を使います。

作業ディレクトリは、git のリポジトリの中でなければなりません。

--repo が今の git remote と食い違うときは、warning を出して --repo を使います。

remote の URL から owner/repo を読めないときは、--repo と比べません。--repo があれば、warning を出して --repo を使い、無ければ止まります。

コミットの数は、GitHub の compare API の ahead_by で数えます。呼ぶ先は GET /repos/{owner}/{repo}/compare/{release_branch}...{develop_branch} です。git fetch は打たず、手元の ref も動かしません。リモートにだけあるコミットも数えます。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか --project で選びます。

作業ディレクトリは、git のリポジトリの中でなければなりません。GitHub のリポジトリに、開発ブランチとリリースブランチが要ります。remote の origin（無ければ最初の remote）は、タグの確認に使います。

設定ファイルに、リポジトリの develop_branch と release_branch が要ります（pecot project link で設定します）。リリースの種類が nx のときは要りません。

ホストの GitHub トークンと、alert を読む権限が要ります。

使用例

CHANGELOG から見つけた版で、リリースを確かめます。

pecot release check

渡した版のリリースを確かめます。

pecot release check 0.6.1

monorepo の 1 つのパッケージのリリースを確かめます。

pecot release check 0.6.1 --package pecot-workflow

引数

--package

monorepo のパッケージの名前です。 省くと、値はありません。設定ファイルでリポジトリに packages を設定しているときは必須です。

指定:

省略可

型:

string

MCP での名前:

package

--project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

指定:

省略可

型:

string

MCP での名前:

project

<version>

リリースする版です。 省くと、CHANGELOG の最初の ## [X.Y.Z] の見出しの版です。Unreleased の見出しは飛ばします。

指定:

省略可

型:

string

MCP での名前:

version

出力

版の行、タグの行、空行、その版のリリースノートです。リリースの種類が nx のリポジトリでは、標準出力に何も書きません。

MCP の結果の項目

項目名

型

説明

version

string

リリースする版です。リリースの種類が nx のときは入りません。nx ではアラートだけを確かめます。

tag

string

作るタグです。リリースの種類が nx のときは入りません。

releaseNotes

string

CHANGELOG から取ったリリースノートです。リリースの種類が nx のときは入りません。

commitCount

integer

リリースブランチから develop ブランチまでのコミットの数です。リリースの種類が nx のときは入りません。

skipped

array

機能が無効なので飛ばした確認の文の配列です。例は Dependabot alerts (feature disabled) です。飛ばした確認が無ければ空です。

dependabotAlerts

object

Dependabot アラートの状態です。読めなかったときは入りません。リリースは止めません。enabled・openCount・alertsUrl を必ず持ち、maxSeverity は、開いたアラートがあるときだけ入ります。

エラーと警告の項目については、共通仕様の出力を参照してください。

  • 標準エラー: alert の種類ごとに、count の行、skipped の行、warning の行のどれかを出します。code scanning と secret scanning には、error の行も出します。リリースするコミットの count の行を出します。--repo が git remote と違うときは、warning の行を出します。失敗したときは、error の行を出します。コミットの数を数えられなかったときは、error: could not count the commits from <release> to <develop>: ... の行を出します。remote の URL から owner/repo を読めず --repo があるときは、warning: using --repo <owner/repo> で始まる行を出します。行の末尾は (could not read the repository from the URL of the Git remote <name>) です。--repo も無いときは、error: the repository is ambiguous の行に、理由と --repo の案内の行を続けます。

no-active-project

1

repo-not-in-project

対象のリポを含むプロジェクトの設定がありません。--project で選んだ設定が対象のリポを含まないときも含みます。

project-not-found

1

invalid-input

1

repo-setting-missing

develop_branch か release_branch が未設定です。

1

preflight-failed

リリースの確認に通りません。次のどれかです。alert の確認が失敗しました。CHANGELOG かその中の版が見つかりません。タグが既にあります。リリースするものがありません。git のコマンドが失敗しました。

1

invalid-input

知らないオプションなど、コマンドラインの誤りがあります。

2

github-auth

コミットの数を数えるとき、GitHub トークンが見つからないか、GitHub がトークンを拒みました。

1

github-not-found

コミットの数を数えるとき、GitHub にブランチかリポジトリが見つかりません。

1

github-rate-limit

コミットの数を数えるとき、GitHub API のレート制限に当たりました。

1

github-api

コミットの数を数えるとき、GitHub API がほかのエラーを返しました。

1

project-root-not-found

プロジェクトのルートを決められません。

1

other

ほかの名前に当たらない失敗です。GitHub へ届かず、コミットの数を数えられないときも含みます。MCP のツールでは、コマンドの想定外の例外も含みます。

1

session-directory-unresolved

MCP のツールだけで起きます。サーバがセッションのディレクトリを決められず、コマンドを動かしません。

1

GitHub と作業ツリーのどちらにも、何も作りません。手元の ref も動かしません。open の alert か読めない alert が Dependabot だけのときは、warning を出して終了コード 0 で終わります。
