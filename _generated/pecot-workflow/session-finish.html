session finish

session finish

マージ済みの PR の後片付けをします。関連する Issue を閉じ、ブランチを削除し、ローカルを片付けます。

マージ済みの PR の後片付けをします。関連する Issue を閉じ、ローカルのチェックアウトを開発ブランチに戻します。オプションを付けると、リモートブランチも削除します。

関連する Issue は、PR のリポの closing issues と、head ブランチ名の末尾の番号の Issue です。base が既定ブランチでない PR では、本文の Closes・Fixes・Resolves の後に書いた、PR のリポの Issue も含めます。GitHub がキーワードを読むのは既定ブランチ宛ての PR だけなので、そこで読まない所（コードブロック・インラインコード・HTML コメントの中）は数えません。

閉じた理由を残すため、すでに閉じた Issue は閉じ直さず、unchanged の行を書きます。状態を読めない Issue も閉じず、warning の行を書きます。

Epic と、sub-issue を持つ Issue は閉じず、skipped の行を書きます。

Issue を閉じた後、その Issue を待っている Issue を読み、判定に合わせてボードの列と Status の札を動かします。着手の跡がある Issue は動かしません。判定に、閉じた Issue が済んだ前提として出ていないときは、約 1.5 秒後に 1 回だけ読み直します。それでも出なければ、後で pecot board sync を打つよう warning で知らせ、列を動かしません。

判定が変わった Issue を、標準出力の Readiness changed: の行の下に、1 件 1 行で出します。行は - #13 stackable on #12 -> startable の形です。マージ前の判定は、閉じた Issue と PR がまだ開いていたものとして出します。変わった Issue が無ければ、何も出しません。

待っている Issue のうち、種類が stack でブランチか PR を持つものは、この PR の上に積んだ段です。その作業ディレクトリでブランチを載せ直すよう warning で知らせます。そのブランチは削除しません。

選んだプロジェクトのボードに無い Issue と、Ready・Blocked・Active・In Review の外の列の Issue は、動かさず、一覧にも出しません。

--delete-branch を付けると、リモートの head ブランチを削除します。

ローカルのチェックアウトを切り替える先は、worktree の中では、pecot worktree add が記録した wtN です。記録が無ければ、worktree の親ディレクトリの名前が wtN か base のときに、その名前を使います。worktree の外では、develop_branch です。切り替えた後、remote の origin から pull します。origin が無ければ、最初の remote を使います。その後、ローカルの head ブランチを git branch -D で削除します。

今のディレクトリのリポジトリが PR のリポジトリと違うときは、ローカルの片付けを飛ばします。

ローカルの片付けの後、.pecot/state/ の下のフラグを消します。消すのは、.pecot-base・.pecot-session-title です。古い版の .pecot-quick-mode・.pecot-active が残っていても触れません。

--skip-local-cleanup を付けると、ローカルを片付けず、これらのフラグも残します。

--dry-run を付けると、結果の行の代わりに dry-run: would の行を書き、何も変えません。

2 回目の実行の後の状態は 1 回目と同じですが、書く行は違います。リモートブランチは unchanged として知らせ、ローカルのブランチへの git branch -D は warning になります。

参照の短い形の N は、pecot --repo の値で補います。その値が無ければ、今のディレクトリの git remote で補います。

--project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか --project で選びます。

ホストの GitHub トークンが要ります。

PR は、マージ済みでなければなりません。

使用例

マージ済みの PR の後片付けをし、リモートブランチも削除します。

pecot session finish example-org/my-repo/123 --delete-branch

何も変えずに、行う予定を出します。

pecot session finish example-org/my-repo/123 --dry-run

引数

<pr_ref>

PR の参照です。owner/repo/N か、番号だけの短い形 N で渡します。 短い形の N は、pecot --repo の値で補います。その値が無ければ、今のディレクトリの git remote で補います。

指定:

必須

型:

string

pr_ref

--delete-branch, -d

ブランチを削除するかどうかです。

指定:

省略可

MCP での名前:

delete_branch

既定値:

false

--dry-run, -n

実際には片付けず、予定だけを出すかどうかです。

指定:

省略可

boolean

MCP での名前:

dry_run

既定値:

false

--project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

指定:

省略可

型:

string

MCP での名前:

project

--skip-local-cleanup

ローカルのブランチの切り替えと削除を飛ばすかどうかです。

指定:

省略可

型:

boolean

MCP での名前:

skip_local_cleanup

既定値:

false

出力

判定の変わった Issue があるときだけ、Readiness changed: の行と、Issue ごとの - <Issue> <前の判定> -> <後の判定> の行を出します。無ければ何も出しません。

MCP の結果の項目

項目名

型

説明

closedIssues

array

このコマンドが閉じた Issue の番号の配列です。dry_run のときは、閉じる予定の番号です。既定ブランチ宛ての PR では、GitHub がマージで先に閉じるので、ふつうは空です。

skippedIssues

array

PR が閉じる対象のうち、閉じなかった Issue の配列です。要素は number と reason を持ちます。reason は epic（保護している）・already-closed・not-found・failed（warnings を見る）のどれかです。already-closed には、PR のマージで GitHub が先に閉じた Issue も入ります。

deletedBranches

array

削除したブランチの配列です。dry_run のときは、削除する予定のブランチです。要素は branch と location（remote か local）を持ちます。

readinessChanges

array

判定が変わった Issue の配列です。要素は issue（#N か owner/repo#N）・from・to を持ちます。from と to は blocked・startable・stackable on #N のどれかです。無ければ空の配列です。

restack

array

この PR の上に積んだ段の配列です。要素は issue と、Issue につながるブランチがあれば branch を持ちます。その作業ディレクトリで載せ直しが要ります。無ければ空の配列です。

currentBranch

string

ローカルの後片付けのあとのブランチです。後片付けを飛ばしたときは入りません。

dryRun

true

dry_run のときだけ true で入ります。何も変えていません。

エラーと警告の項目については、共通仕様の出力を参照してください。

  • 標準エラー: 標準エラーに、閉じる Issue の count の行を出し、続けて手順ごとに結果の行を 1 つ出します。結果の行は、closed・skipped・unchanged・deleted・moved・set・updated です。--dry-run のときは、結果の行の代わりに dry-run: would の行を出します。失敗した手順には、warning の行を出します。ローカルの片付けを飛ばしたときも、warning の行を出します。上に積んだ段があるときと、待っている Issue の判定を確かめられないときも、warning の行を出します。
