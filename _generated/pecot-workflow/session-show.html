session show

session show

セッションのブランチ、リポジトリ、作業中の Issue を出します。

今のブランチ、remote の origin（無ければ最初の remote）のリポジトリ、セッションの作業中の Issue を出します。

ブランチと、remote の origin（無ければ最初の remote）のリポジトリは、--directory で読みます。

作業中の Issue は owner/repo#N です。owner/repo はその remote のリポジトリで、N はブランチ名の最後のスラッシュより後ろにある末尾の番号です。remote を読めないか URL の形が合わないとき、ブランチ名の最後の区切りが数字だけでないとき、番号が 0 のとき、detached HEAD のときは、作業中の Issue はありません。

古い版の .pecot/state/.pecot-active が残っていても読みません。

Active Issue の行には、owner/repo#N を出します。作業中の Issue が無ければ none を出します。

作業中の Issue があるときは、Active Issue の節が続きます。GitHub から読んだ Issue の番号・題・状態を載せます。

Issue の本文が空でなければ、その節に本文が続きます。本文は、この Markdown の出力にだけ出し、MCP の結果には入れません。

Issue を GitHub から読めないときは、warning の行を出し、節を出しません。

Active Issue の節を出し、プロジェクトのルートの .pecot/state/.pecot-base が積んだ先の Issue を指すときは、Stack の節が続きます。節には、ブランチ・Issue・その PR を書いた base の行を載せます。PR は、fork からではない open の PR です。それが無ければ最新の PR、それも無ければ no PR で、読めないときは PR unknown です。

Stack の節の base の行の次に、needs restack の行（yes か no）を載せます。下の段の remote の先頭が記録の位置と違うときと、下の段の PR がマージ済みのときが yes です。ただし、ブランチが新しい base の上に載り終えていれば no です（pr restack と同じ判断です）。

needs restack の行は、git fetch をせずに remote へ尋ねて決めます。remote に届かないときは、行を出しません。下の段のブランチが消えていて PR がマージされていないときも、行を出しません。

アクティブな Issue の着手の判定が blocked のときは、Stack の節に readiness の行も載せます。

今のブランチを base にした、同じリポジトリの open の PR があれば、Stack の節に PR ごとの stacked above の行を載せます。積んで着手していない作業ディレクトリでも載せます。

.pecot/state/.pecot-base の記録は、--directory の git リポジトリの toplevel のものを読みます。プロジェクトのルートの記録を、別の worktree や clone の作業には使いません。

記録が無いときは、積んだ先を求めます。作業中の Issue の判定が stackable で、判定の示すブランチの変更をブランチが持てば、Stack の節にその base を出します。変更を持つとは、同じコミットか、そのブランチを載せ直した後の同じ patch を持つことです。そのブランチが自分のコミットを持たなければ、その先頭がブランチの祖先であることです。求めるときに読んだ判定は、readiness の行にも使います。

Stack の節は、Active Issue の節と同じ設定とクライアントを使います。Active Issue の節を出さないときは、Stack の節も出しません。

このコマンドは診断用です。読めない値は、unknown か none と出すか省き、コマンドは失敗しません。

何も書き込みません。

--project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

使用例

今のリポジトリのブランチ・リポジトリ・作業中の Issue を出します。

pecot session show -D .

引数

--directory, -D

対象の Git リポジトリのパスです。絶対パスと相対パスのどちらも渡せます。

指定:

必須

型:

string

MCP での名前:

directory

--project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

指定:

省略可

型:

string

MCP での名前:

project

出力

Session status の見出しがある Markdown です。Branch・Repository・Active Issue の行を出します。作業中の Issue を読めたときは Active Issue の節を、作業を積んでいるときは Stack の節を出します。

MCP の結果の項目

項目名

型

説明

branch

string

今のブランチです。読めないときは入りません。

repository

string

git remote のリポジトリです。owner/repo の形です。読めないときは入りません。

activeIssue

object

セッションの作業中の Issue です。無いときは入りません。reference（owner/repo/N。issue_ref にそのまま渡せる形）を持ちます。title と state（OPEN か CLOSED）は、GitHub から読めたときだけ入ります。本文は入りません。

stack

object

作業を積んでいる先です。積んでいないときは入りません。branch（積んでいる先の base ブランチ）と stackedOn（積んでいる Issue。owner/repo/N）を持ちます。pullRequest（number と state）は、base ブランチの PR があり、読めたときだけ入ります。needsRestack は、載せ直しが要るかで、決められたときだけ入ります。readiness は、作業中の Issue が blocked のときだけ入ります。

stackedAbove

array

今のブランチを base にした、同じリポジトリの open の PR の一覧です。number と branch（head のブランチ）を持ちます。無いときと読めないときは入りません。

エラーと警告の項目については、共通仕様の出力を参照してください。

  • 標準エラー: 標準エラーに warning の行を出すのは、次のときです。作業中の Issue があり、それを読めないとき。base のブランチの PR を読めないとき。.pecot-base の形が誤っているとき。アクティブな Issue の着手の判定ができないとき。記録が無く積んだ先を求められないとき（warning: cannot infer the stacked base）。作業中の Issue のリポを含む設定が無いか使う設定が決まらないときと、選んだ設定ファイルの内容が不正なときも含みます。プロジェクトのルートを決められないときは、error の行を出します。

エラー

エラー名

説明

終了コード

invalid-input

--directory が無いか、無いパス・ファイル・読めないディレクトリのどれかです。ほかのコマンドラインの誤りも含みます。

2

project-root-not-found

プロジェクトのルートを決められません（error の行を出します）。

1

other

ほかの名前に当たらない失敗です。MCP のツールでは、コマンドの想定外の例外も含みます。

1

session-directory-unresolved

MCP のツールだけで起きます。サーバがセッションのディレクトリを決められず、コマンドを動かしません。

1

ブランチ・リポジトリ・アクティブな Issue を読めないときも、終了コード 0 で終わります。作業中の Issue があり、選んだ設定ファイルの内容が不正なときも同じです。
