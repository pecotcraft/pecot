pr restack

pr restack

積んだブランチを、base にしたブランチの新しい位置へ載せ直します。

今のブランチを、積んで着手したときの base の記録を使って、下の段のブランチの新しい位置へ載せ直します。

--check を付けると、載せ直しが要るかだけを出します。変わるのは、git fetch が進める手元の追跡参照だけです。

積んでいないブランチ（開発ブランチからの着手の記録か、記録が無く積んだ先も求まらないもの）は、載せ直しません。

作業ディレクトリの worktree に .pecot/state/.pecot-base が無いときは、積んだ先を求めます。作業中の Issue の判定が stackable で、判定の示すブランチの変更をブランチが持てば、そのブランチに積んだものとします。変更を持つとは、同じコミットか、そのブランチを載せ直した後の同じ patch を持つことです。そのブランチが自分のコミットを持たなければ、その先頭がブランチの祖先であることです。

そうでなければ、開発ブランチからの着手とします。判定を読めないか blocked のときと、GitHub に届かないとき、追跡参照が無いときは、warning: cannot infer the stacked base の行を出します。求めた結果は書きません。

載せ直しが要るのは、下の段の remote の先頭が記録の位置と違うときと、下の段の PR がマージ済みのときです。マージ済みなら開発ブランチへ載せ直し、base の記録を開発ブランチからの着手に変えます。

ブランチが新しい base の上に載り終えていれば、記録が古くても rebase をしません。載り終えているとは、新しい base がブランチの履歴にあり、記録の位置もブランチの履歴にあるなら、それが新しい base の履歴にもあることです。push と記録の書き直しは、--check なしの pr restack が行います。remote のブランチが同じ木で新しい base の上にあれば、push せずに remote のブランチに合わせます。

rebase の後、remote のブランチにだけあるコミットがあれば止まります。push がそのコミットを消すためです。ブランチは載せ直しの前の位置へ戻します。

同じ変更かは、載せ直しの前と後のブランチの両方と比べます。GitHub が書き換えたコミットを、別の変更と見ないためです。

git rebase --no-update-refs --onto <新しい base> <記録の位置> を打ちます。

記録の位置がブランチの履歴に無いときは、別の点から rebase を始めます。下の段の追跡参照からの fork-point を使い、求まらなければ新しい base との merge-base を使います。下の段がマージ済みでも同じです。

結果の木が remote のブランチと同じで、remote のブランチが新しい base の上にあれば、remote のブランチに合わせ、push しません。

そうでなければ、fetch した位置を期待の値にした --force-with-lease で push します。pre-push のフックを含めて、10 分まで待ちます。remote に無いブランチは push しません。

載せ直しの後、base の記録の位置を、ブランチと新しい base の merge-base に書き直します。

開発ブランチへ載せ直した後、ブランチの開いている PR の本文を変えずに保存し直します。GitHub は、積んだ PR の Closes を Issue とリンクせず、base を付け替えても本文を読み直さないためです。

保存し直すのは、PR の base がリポの既定のブランチで、本文の Closes などの Issue に、まだリンクになっていないものがあるときだけです。GitHub がリンクにするのは、既定のブランチに向いた PR だけです。

保存し直しの失敗は warning の行にとどめ、終了コードは 0 のままです。base の記録は書き直し済みなので、打ち直しても保存し直しません。warning の行は、GitHub で本文を変えずに保存し直す案内を添えます。

衝突したら、衝突したファイルを出し、rebase を途中のまま残します。途中の記録を書き、終了コード 3 で終わります。

--continue は、衝突を解いて git add した後に続けます。--abort は、載せ直しの前の位置に戻します。どちらも途中の記録だけを読み、pecot が始めていない rebase は動かしません。

--check・--continue・--abort は、1 つだけ渡せます。

--dry-run を付けると、fetch と判断までを行い、する予定を dry-run の行に出します。rebase・push・記録の書き込みは行いません。

書き換えるのは、今の作業ディレクトリのブランチだけです。ほかの worktree には触れません。

--project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか --project で選びます。

積んで着手した作業ディレクトリで打ちます（pecot session start が base の記録を書きます）。

使用例

今のブランチに載せ直しが要るかを確かめます。

pecot pr restack --check

今のブランチを載せ直して push します。

pecot pr restack

衝突を解いて git add した後に、続けます。

pecot pr restack --continue

載せ直しの前の位置に戻します。

pecot pr restack --abort
