# Quickstart: pecot-coordinator プラグインの確かめ方

各フェーズの終わりに流す確かめ。書き込みは `pecotcraft/pecot-sandbox` とボード「pecot sandbox」だけに行う。書き込む前に `plugins/pecot-workflow/CONTRIBUTING.md` の「3. 試験環境」を読む。

## 1. 検証のフェーズ（Phase 1〜3）

| 確かめ | 手順 | 期待 |
|---|---|---|
| 振り分け | 今のプロジェクト指示の文を 1 つずつ、[contracts/project-instruction-values.md](contracts/project-instruction-values.md) の分け方で振り分ける | どの文も「固有の値」か「スキルへ移す」のどちらかに入る |
| 公式の MCP の手 | [contracts/github-io.md](contracts/github-io.md) の「未確認」の行を、クラウドのスレッドから sandbox に書く | 本文とボードの欄が、今の pecot-workflow が書く形と同じ |
| `actions/` の token | sandbox に `workflow_dispatch` のワークフローを置き、[contracts/actions-interface.md](contracts/actions-interface.md) の操作を App の token と `GITHUB_TOKEN` で試す | 処理ごとに通る token が決まる |
| claude.ai への配布 | 個人の Add marketplace で、`bin/` を外したプラグインを入れる。coordinator とクラウドのスレッドで、スキルの一覧を読ませる | coordinator とスレッドの両方で、入れたスキルが出る。版を上げると届く |

結果は `specs/031-pecot-coordinator/verification/` に書く。

## 2. `actions/` と雛形（Phase 4〜6）

1. sandbox の `.github/workflows/` に、`actions/templates/` の雛形を置く。`uses:` は確かめるブランチの ref を指す
2. sandbox で PR を作ってマージし、Issue を動かす
3. 期待: ボードの同期・マージの後の片付け・アラートの同期が、今の雛形と同じ結果になる。リモートのブランチは、リポの設定で消える
4. pecot-workflow の MCP のツールの一覧に、`auto_*`・`review_finish`・`board_sync`・`tracker_sync` が無い
5. 古い雛形を置いた sandbox で `workflow doctor` を動かすと、古い雛形として返る

## 3. `bin/` をなくしたプラグイン（Phase 7〜9）

1. `claude plugin validate --strict` を 3 つに通す
2. 手元の Claude Code・GitHub Copilot CLI・クラウドのスレッドで 3 つを入れ直し、npx で npm の版の MCP のサーバが起動し、スキルとフックが今どおり動く。クラウドの VM で、npx と build の前の依存の install が npm に届く
3. claude.ai の Add marketplace で 3 つが入る
4. 作業ツリーで build し、リポの外で `npx -y @modelcontextprotocol/inspector@<固定の版> --cli node <作業ツリー>/plugins/<名前>/cli/dist/<サーバ>.js --method tools/list --format json` で、直したツールが出て呼べる。CLI の入口が無い
5. pecot-visual は、Claude Code でスライドのファイルを編集すると、`mcp_tool` のフックが lint と参照の検証のツールを呼び、結果がエージェントに届く

## 4. pecot-workflow の作り替え（Phase 10〜12）

クラウドのスレッドで、sandbox の Issue を 1 件、w-active → 実装 → w-pr → マージ待ちまで流す。

- 期待: Issue・PR の本文・ボードの欄・Development 欄・blocked-by が、手元の RC のスレッドで流したときと同じ
- 期待: スレッドが GraphQL・REST を直に呼ばない。プロキシの 403 と「Generated by Claude Code」が出ない
- 期待: 手の無い操作で、利用者に頼む手順が 0 件

## 5. pecot-coordinator（Phase 13〜14）

1. claude.ai のプロジェクトに pecot-c を入れ、プロジェクト指示を固有の値だけにする
2. Ready の Issue を 2 件置き、coordinator に割り振らせる
3. 期待: coordinator がスキルに従い、空いたスレッドを起動して割り振る。利用者に上げる判断は、計画の承認・マージ・仕様を変える判断だけ
4. 期待: 利用者が答える質問の数が、今のプロジェクト指示で流したときより増えない（SC-012）
