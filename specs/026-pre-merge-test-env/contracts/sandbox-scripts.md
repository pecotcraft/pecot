# Contract: 比べと片付けのスクリプト

このリポの開発で使う。プラグインに同梱されて導入先にも写るが、引数なしでは検証用だけに触る。置き場は `plugins/pecot-workflow/scripts/sandbox/`、テストは `plugins/pecot-workflow/cli/tests/sandbox/`（vitest）。
どちらも `gh` で GitHub を読む。テストは、偽の `gh` を PATH に置いて確かめる。

## `sandbox-diff.sh`（FR-017）

このリポと検証用の設定を比べ、ずれを出す。何も書き換えない。

| 入力 | 中身 |
|---|---|
| 引数なし | このリポ（`pecotcraft/pecot`・Projects の 1 番）と検証用（`pecotcraft/pecot-sandbox`・Projects の 3 番）を比べる |
| `sandbox-diff-items.json` | 比べる項目・比べない項目とその訳・読み飛ばすキー |

| 場合 | 出力 | 終了コード |
|---|---|---|
| ずれが無い | 「ずれは 0 件」の 1 行 | 0 |
| ずれがある | 件数の 1 行と、ずれごとに項目の名前・このリポの値・検証用の値 | 1 |
| 読めない（認証・通信・権限） | `error:` で始まる行に、読めなかった先と訳 | 2 |
| 比べるキーが応答に無い（`null` を含む） | `error:` で始まる行に、読んだ先とキーの名前 | 2 |

ずれは 1 件を 3 行で出す。1 行目が項目の名前（`ruleset main / merge_queue` の形）、2 行目が字下げした `このリポ: <値>`、3 行目が字下げした `検証用: <値>` だ。値は、文字列ならそのまま、ほかは 1 行の JSON で出す。

決まりは次のとおり。

- 比べるのは、`compare` が `true` の項目だけ。`false` の項目は、ずれとして出さない
- 比べるキーが無いときは、権限の不足とみなして止める。両方に無くても「同じ」としない
- 読み飛ばすキー（`id`・`node_id`・日時・`integration_id` など）の違いは、ずれにしない
- ruleset は、個別の取得（`rulesets/{id}`）で読む。上の階層から来た ruleset は比べない
- このリポだけの運用の ruleset（`pages-store`・`release-tags`）は、名前で外して比べない（FR-008）
- ボードは、項目の名前・型・選択肢の名前と並びを比べる。列の項目は、名前の違い（`pecot-workflow-<名前>`）を読み替えて比べる
- ボードの設定ファイルは、名前の形を比べる。項目の名前は `config-file`
  - 各リポの `main` の `.pecot/config/projects/` から、中身の `host`・`owner`・`project.number` が比べるボードと同じファイルを選ぶ。読めない JSON は飛ばす
  - 名前が `<host>_<owner>_<number>.json` なら、その形を出す
  - 中身に `workflow_suffix` があり、名前が `<host>_<owner>_` で始まって `_<workflow_suffix>.json` で終わるなら、`<host>_<owner>_<題>_<suffix>.json` を出す
  - どちらでもなければ名前をそのまま出す。2 つ以上なら名前順に `、` でつなぐ
  - ディレクトリが無いときは、読めないとして止める
- `ci.yml` は、有無だけを比べる
- `pecot-board-sync.yml` と `pecot-review.yml` は、有無と中身を比べる。比べる相手は、このリポの main にある同じファイルだ（FR-032）
  - 中身が違えば、両方の値を `blob <sha>、<行番号> 行目: <その行>` の形で出す。行は、両方で違う最初の行にする
- 片方にしか無い項目は、無い側を「なし」と出す

テストでは、次の場合を確かめる。

| 場合 | 期待 |
|---|---|
| 2 つの設定が同じ | 0 件、終了コード 0 |
| 検証用の必須チェックが 1 つ少ない | 1 件。項目の名前と、両方の値が出る。終了コード 1 |
| 検証用に merge queue の規則が無い | 1 件。検証用の値が「なし」 |
| 検証用に CodeQL の規則が無い（比べない項目） | 0 件 |
| 検証用に `pages-store`・`release-tags` の ruleset が無い（比べない項目） | 0 件 |
| ボードの列の値が 1 つ多い | 1 件 |
| `id` と日時だけが違う | 0 件 |
| 検証用の進行の欄だけが `pecot-status` | 2 件（`board-fields / pecot-status` と `board-fields / pecot-workflow-*`） |
| 両方の設定ファイルが同じ形 | 0 件 |
| 検証用の設定ファイルだけが今の形 | 1 件。項目の名前は `config-file` で、両方の形が出る |
| 検証用に比べるボードの設定ファイルが無い | 1 件。検証用の値が「なし」 |
| 別のボードを指す設定ファイルがある | 0 件 |
| 同じボードの設定ファイルが 2 つある | 1 件。形を名前順につなぐ |
| どちらの形にも合わない名前 | 1 件。名前をそのまま出す |
| 設定のディレクトリが無い | `error:` の行、終了コード 2 |
| 検証用の `pecot-board-sync.yml` の中身が、このリポの main と違う | 1 件 |
| 検証用の `pecot-review.yml` の中身が、このリポの main と違う | 1 件。項目の名前は `workflows / pecot-review.yml` |
| 検証用に `pecot-review.yml` が無い | 1 件。検証用の値が「なし」 |
| `gh` が認証の失敗を返す | `error:` の行、終了コード 2 |
| 比べるキーが `null` か無い（両方とも `null` の場合を含む） | `error:` の行、終了コード 2 |
| git の作業ツリーの外で打つ | `error:` の行、終了コード 2 |

## `sandbox-sweep.sh`（FR-010、FR-011）

確かめで作ったものを、検証用から片付ける。

| 入力 | 中身 |
|---|---|
| 引数なし | 名前の形（[data-model.md](../data-model.md) の「確かめで作ったもの」）に合うものを、すべて片付ける |
| `--issue <番号>` | その Issue の番号を持つものだけを片付ける |
| `--dry-run` | 片付けるものを出すだけで、書き換えない |

| 場合 | 出力 | 終了コード |
|---|---|---|
| 片付けた | 片付けたものを 1 行ずつ（種類と名前） | 0 |
| 片付けるものが無い | 「片付けるものは 0 件」の 1 行 | 0 |
| 一部が失敗した | 失敗したものを `error:` の行で出し、残りは続ける | 1 |
| 引数が違う・一覧を読めない | `error:` で始まる行。何も書き換えない | 2 |

決まりは次のとおり。

- 書き換える先は、検証用のリポとボードだけ。リポやボードを指す引数は持たない。`--issue` は数字だけを受ける
- `gh` の呼び出しは、すべて検証用を名指しする。`-R pecotcraft/pecot-sandbox` か、`repos/pecotcraft/pecot-sandbox/...` の `gh api` にする。作業ツリーで打つので、省くと cwd のリポに向く
- 対象は、ブランチ・開いた PR・開いた Issue・それらのアーカイブされていないカード・リリースとタグの 5 つ。名前の形は data-model.md に従う。閉じた Issue のカードも拾う
- `--issue <番号>` は、`cuj/<番号>-` のように `-` まで含めて比べる。`--issue 456` は `cuj/4560-…` を拾わない
- 片付ける順は、PR を閉じる → ブランチを消す → Issue を閉じる → カードをアーカイブする → リリースとタグを消す。ブランチを先に消すと GitHub が PR を閉じ、後の `gh pr close` が失敗するため
- PR は `--delete-branch` を付けずに閉じる。付けると、手元のブランチまで消える
- 一覧は、すべてページ送りで読む。カードは `gh api graphql` で `items(first:100, after:…)` を送る
- 名前の形に合わないブランチ・PR・Issue には触らない。`main` と、検証用の設定のファイルは消さない
- マージ済みの PR と、消えたブランチは、片付け済みとして数えない
- 2 回続けて動かしても、2 回目は 0 件で終わる
- 一覧で拾った Issue・PR は、1 件ずつ取る API（`issues/{番号}`）で今の状態を見て、閉じていれば数えない。一覧の API は、閉じた直後の Issue・PR を開いたまま返すことがある（2026-11-17 に検証用で確かめた）

テストでは、次の場合を確かめる。

| 場合 | 期待 |
|---|---|
| 形に合う開いた PR・ブランチ・Issue がある | 3 つとも片付ける |
| 形に合わない PR とブランチもある | 形に合うものだけを片付ける |
| `--issue 456` で、456 と 457 のものがある | 456 のものだけを片付ける |
| `--dry-run` | 一覧だけを出し、`gh` の書き込みを呼ばない |
| 片付けるものが無い | 0 件、終了コード 0 |
| ブランチの削除が 1 つ失敗する | `error:` の行を出し、残りを片付けて、終了コード 1 |
| タグ `cuj/456-ab12-tgz` のリリースがある | リリースとタグを消す。`v*` のリリースは残す |
| Issue の題が `[Task] [cuj 456-ab12] …` | 題の途中の `[cuj …]` を拾う |
| ブランチ `cuj/456-ab12/7` と `cuj/4560-ab12` があり、`--issue 456` | `cuj/456-ab12/7` だけを消す |
| 書き込みの呼び出し | すべて `pecotcraft/pecot-sandbox` か、`pecotcraft` の Projects の 3 番を指す |
| 同じ乱数の PR とブランチがある | PR を閉じてから、ブランチを消す |
| 一覧には開いて出るが、1 件ずつ取ると閉じている Issue・PR がある | 数えず、閉じる呼び出しもしない |
| そのような Issue だけがある | 「片付けるものは 0 件」、終了コード 0 |
