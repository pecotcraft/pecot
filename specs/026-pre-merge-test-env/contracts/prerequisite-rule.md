# Contract: フェーズの前後の決まり

配布物の変更。フェーズの前提の種類（積める・マージを待つ）を決める文を、4 か所で直す（FR-028）。

## 種類を決める問い

| 今 | 直した後 |
|---|---|
| 前提の変更が手元のブランチの下にあれば、このフェーズの実装と確認ができる。このときは「積める」 | 前提の変更を、手元のブランチか試験環境で動かして、このフェーズの実装と確認ができる。このときは「積める」 |
| 前提の変更が開発ブランチに入っていないと、このフェーズの実装か確認ができない。このときは「マージを待つ」 | 前提の変更が開発ブランチに入っていないと、手元のブランチと試験環境のどちらでも、このフェーズの実装か確認ができない。このときは「マージを待つ」 |

試験環境は、開発ブランチに入れる前の変更を動かして確かめる場所を指す。プロジェクトの文書に、その場所で動かす手順があるときだけ使う。無いときは、手元のブランチだけで判断する。

置き場ごとに主語と文の形（tasks の引数・定義の文・表のセル）は変わる。どの置き場にも、芯の 2 句「前提の変更を、手元のブランチか試験環境で動かして」と「手元のブランチと試験環境のどちらでも」を入れる。

## 「マージを待つ」になる例

| 例 | 扱い | 訳 |
|---|---|---|
| 既定のブランチから配られるプラグインを使う | 外す | 直したプラグインは、ブランチの中身を読み込んで確かめられる |
| 既定のブランチから配られる action を使う | 残す | action は、既定のブランチの中身を入れる |
| 公開したパッケージを使う | 残す | パッケージは、公開の後にしか取れない |
| リリースの後の実物で確かめる | 残す | リリースの後にしか、実物が無い |
| 開発ブランチの CI やリリースのワークフローが、前提の変更を使う | 残す | 開発ブランチで動く仕組みは、開発ブランチに入るまで前提の変更を使えない |

## 直す場所

| 置き場 | 直す文 |
|---|---|
| `skills/w-breakdown/SKILL.md` の Step 7 の引数 | 種類を決める問いの 2 行と、「マージを待つ」になる例 |
| `skills/w-help/references/issue-flow-rules.md` | `merge` の説明の文と例 |
| `skills/w-help/references/spec-driven-workflow.md` | 「マージを待つ」の説明の行。例の行（action）は残す |
| `skills/w-ready/SKILL.md` | 種類の表の「当たるとき」の 2 行 |
| `skills/w-issueize/SKILL.md` | 直す文が無い。種類を決める文を持たず、表の読み方と例の行（action）だけを持つ |

- 表の形（4 列）と、`wait: merge`・`reason` の扱いは変えない
- CLI のコードと、定義書は変えない

## 確かめ

| 場合 | 期待 |
