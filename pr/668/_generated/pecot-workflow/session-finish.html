Clean up after merge

Clean up after merge

session_finish

マージ済みの PR の後片付けをします。関連する Issue を閉じ、ブランチを削除し、ローカルを片付けます。

マージ済みの PR の後片付けをします。関連する Issue を閉じ、ローカルのチェックアウトを開発ブランチに戻します。delete_branch を付けると、リモートブランチも削除します。

関連する Issue は、PR のリポの closing issues と、head ブランチ名の末尾の番号の Issue です。base が既定ブランチでない PR では、本文の Closes・Fixes・Resolves の後に書いた、PR のリポの Issue も含めます。GitHub がキーワードを読むのは既定ブランチ宛ての PR だけなので、そこで読まない所（コードブロック・インラインコード・HTML コメントの中）は数えません。

閉じた理由を残すため、すでに閉じた Issue は閉じ直さず、skippedIssues に already-closed で入れます。状態を読めない Issue も閉じず、warnings に入れます。

Epic と、sub-issue を持つ Issue は閉じず、skippedIssues に epic で入れます。

Issue を閉じた後、その Issue を待っている Issue を読み、判定に合わせてボードの列と Status の札を動かします。着手の跡がある Issue は動かしません。判定に、閉じた Issue が済んだ前提として出ていないときは、約 1.5 秒後に 1 回だけ読み直します。それでも出なければ、後で board_sync を呼ぶよう warnings で知らせ、列を動かしません。

判定が変わった Issue を、readinessChanges に入れます。from は、閉じた Issue と PR がまだ開いていたとしたときの判定です。変わった Issue が無ければ、空の配列です。CLI では、標準出力の Readiness changed: の行の下に、1 件 1 行で出します。

待っている Issue のうち、種類が stack でブランチか PR を持つものは、この PR の上に積んだ段です。その作業ディレクトリでブランチを載せ直すよう warnings で知らせ、restack に入れます。そのブランチは削除しません。

選んだプロジェクトのボードに無い Issue と、Ready・Blocked・Active・In Review の外の列の Issue は、動かさず、一覧にも出しません。

delete_branch を付けると、リモートの head ブランチを削除します。

ローカルのチェックアウトを切り替える先は、worktree の中では、worktree_add が記録した wtN です。記録が無ければ、worktree の親ディレクトリの名前が wtN か base のときに、その名前を使います。worktree の外では、develop_branch です。切り替えた後、remote の origin から pull します。origin が無ければ、最初の remote を使います。その後、ローカルの head ブランチを git branch -D で削除します。

今のディレクトリのリポジトリが PR のリポジトリと違うときは、ローカルの片付けを飛ばします。

ローカルの片付けの後、.pecot/state/ の下のフラグを消します。消すのは、.pecot-base・.pecot-session-title です。古い版の .pecot-quick-mode・.pecot-active が残っていても触れません。

skip_local_cleanup を付けると、ローカルを片付けず、これらのフラグも残します。

dry_run を付けると、何も変えずに、閉じる予定の Issue と削除する予定のブランチを結果に入れます。

2 回目の実行の後の状態は 1 回目と同じですが、結果は違います。リモートブランチは deletedBranches に入らず、ローカルのブランチへの git branch -D は warnings に入ります。

参照の短い形の N は、引数 repo の値で補います。その値が無ければ、今のディレクトリの git remote で補います。

project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

ホストの GitHub トークンが要ります。

PR は、マージ済みでなければなりません。

使用例

マージ済みの PR の後片付けをし、リモートブランチも削除します。

{
  "name": "session_finish",
  "arguments": {
    "pr_ref": "example-org/my-repo/123",
    "delete_branch": true
  }
}

何も変えずに、行う予定を返します。

{
  "name": "session_finish",
  "arguments": {
    "pr_ref": "example-org/my-repo/123",
    "dry_run": true
  }
}

引数

pr_ref

PR の参照です。owner/repo/N か、番号だけの短い形 N で渡します。 短い形の N は、引数 repo の値で補います。その値が無ければ、今のディレクトリの git remote で補います。

指定:

必須

型:

string

delete_branch

ブランチを削除するかどうかです。

指定:

省略可

型:

boolean

既定値:

false

dry_run

実際には片付けず、予定だけを返すかどうかです。

指定:

省略可

型:

boolean

既定値:

false

project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

指定:

省略可

型:

string

skip_local_cleanup

ローカルのブランチの切り替えと削除を飛ばすかどうかです。

指定:

省略可

型:

boolean

既定値:

false

出力

MCP の結果の項目

項目名

型

説明

closedIssues

array

このコマンドが閉じた Issue の番号の配列です。dry_run のときは、閉じる予定の番号です。既定ブランチ宛ての PR では、GitHub がマージで先に閉じるので、ふつうは空です。

skippedIssues

array

PR が閉じる対象のうち、閉じなかった Issue の配列です。要素は number と reason を持ちます。reason は epic（保護している）・already-closed・not-found・failed（warnings を見る）のどれかです。already-closed には、PR のマージで GitHub が先に閉じた Issue も入ります。

deletedBranches

array

削除したブランチの配列です。dry_run のときは、削除する予定のブランチです。要素は branch と location（remote か local）を持ちます。

readinessChanges

array

判定が変わった Issue の配列です。要素は issue（#N か owner/repo#N）・from・to を持ちます。from と to は blocked・startable・stackable on #N のどれかです。無ければ空の配列です。

restack

array

この PR の上に積んだ段の配列です。要素は issue と、Issue につながるブランチがあれば branch を持ちます。その作業ディレクトリで載せ直しが要ります。無ければ空の配列です。

currentBranch

string

ローカルの後片付けのあとのブランチです。後片付けを飛ばしたときは入りません。

dryRun

true

dry_run のときだけ true で入ります。何も変えていません。

エラーと警告の項目については、共通仕様の出力を参照してください。

エラー

エラー名

説明

no-active-project

対象のリポを含むプロジェクトの設定が 2 つ以上あり、使う設定が決まりません。アクティブなプロジェクトが候補を指さず、project もありません。

repo-not-in-project

対象のリポを含むプロジェクトの設定がありません。project で選んだ設定が対象のリポを含まないときも含みます。

project-not-found

project の名前の設定がありません。

github-not-found

PR がありません。

pr-state

PR がマージされていません。

invalid-input

pr_ref の形が誤っているか、ほかの引数の誤りがあります。

github-auth

GitHub トークンが見つからないか、GitHub がトークンを拒みました。

github-not-found

GitHub に対象が見つかりません。

github-rate-limit

GitHub API のレート制限に当たりました。

github-api

GitHub API がほかのエラーを返しました。

project-root-not-found

プロジェクトのルートを決められません。

other

ほかの名前に当たらない失敗です。MCP のツールでは、コマンドの想定外の例外も含みます。

session-directory-unresolved

MCP のツールだけで起きます。サーバがセッションのディレクトリを決められず、コマンドを動かしません。

マージされていない PR はそのまま残し、何も変えません。Issue を閉じられなかったときは warnings に入れ、ほかの Issue と後の手順を続けます。巻き戻しはしません。リモートの head ブランチの削除に失敗したときは、warnings に入れて後の手順を続けます。checkout に失敗したときは、pull とブランチの削除を飛ばし、フラグは消します。warnings に入れて飛ばした手順があっても、成功を返します。

機能要件

ID

要件

PW-SESSION-FINISH-01

マージ済みの PR の pr_ref を渡すと、PR のリポの closing issues と head ブランチ名の末尾の番号の Issue を close します。base が既定ブランチでない PR では、本文のコードと HTML コメントの外の Closes / Fixes / Resolves の後の、PR のリポの Issue も close します

PW-SESSION-FINISH-02

Epic か sub-issue を持つ Issue があると、その Issue を close しません

PW-SESSION-FINISH-03

Epic か sub-issue を持つ Issue があると、skippedIssues に epic で入れます

PW-SESSION-FINISH-04

delete_branch を付けて呼ぶと、リモートの head ブランチを削除します

PW-SESSION-FINISH-06

セッションのリポジトリが PR のリポジトリと同じだと、worktree の中なら worktree の wtN の、そうでなければ develop_branch のブランチに切り替えます。wtN は worktree_add の記録で決め、記録が無ければ置き場所の親ディレクトリの名前で決めます

PW-SESSION-FINISH-07

ブランチを切り替えると、origin の remote（無ければ最初の remote）から develop_branch を pull します

PW-SESSION-FINISH-08

pull すると、ローカルの head ブランチを git branch -D で削除します

PW-SESSION-FINISH-09

ローカルの片付けを終えると、フラグのファイルを消します

PW-SESSION-FINISH-10

skip_local_cleanup を付けて呼ぶと、ローカルの片付けをしません

PW-SESSION-FINISH-11

skip_local_cleanup を付けて呼ぶと、フラグのファイルを消しません

PW-SESSION-FINISH-12

dry_run を付けて呼ぶと、何も変えずに、する予定を結果に入れ、dryRun を true にします

PW-SESSION-FINISH-13

呼ぶと、close する Issue を数えます。CLI では、件数を count の行で標準エラーに出します

PW-SESSION-FINISH-14

Issue を close すると、その番号を closedIssues に入れます

PW-SESSION-FINISH-15

ブランチを削除すると、deletedBranches に入れます

PW-SESSION-FINISH-16

リモートの head ブランチが既に無いと、deletedBranches へ入れずに続けます

PW-SESSION-FINISH-17

もしローカルの head ブランチが既に無いなら、warnings に 1 つ入れます

PW-SESSION-FINISH-18

もしセッションのリポジトリが PR のリポジトリと違うなら、warnings に 1 つ入れます

PW-SESSION-FINISH-19

もしセッションのリポジトリが PR のリポジトリと違うなら、ローカルの片付けを飛ばします

PW-SESSION-FINISH-20

もし Issue の close に失敗したなら、warnings に 1 つ入れます

PW-SESSION-FINISH-21

もし Issue の close に失敗したなら、ほかの Issue と後の処理を続けます

PW-SESSION-FINISH-23

もし checkout に失敗したなら、pull と git branch -D を飛ばします

PW-SESSION-FINISH-24

もし PR がマージされていないなら、kind が pr-state の失敗を返し、pr_merge を案内する文を detail に入れます

PW-SESSION-FINISH-25

もし PR がマージされていないなら、何も変えません

PW-SESSION-FINISH-26

もし対象のリポを含む設定が 2 つ以上あり、アクティブなプロジェクトがそのどれも指さないなら、kind が no-active-project の失敗を返します。detail に候補の名前と project の案内を入れます

PW-SESSION-FINISH-27

もし PR を取得できないか、PR が無いなら、失敗を返します

PW-SESSION-FINISH-28

もし pr_ref の形が誤っているなら、kind が invalid-input の失敗を返します

PW-SESSION-FINISH-31

Issue を閉じると、ブランチを消す前に、その Issue を待っている Issue の列と札を判定どおりに動かします

PW-SESSION-FINISH-32

もし待っている Issue に着手の跡があるなら、その列と札を動かしません

PW-SESSION-FINISH-33

待っている Issue の判定が変わると、その Issue を readinessChanges に入れます。CLI では、標準出力の Readiness changed: の下に出します

PW-SESSION-FINISH-34

もし判定の変わった Issue が無いなら、readinessChanges を空の配列にします。CLI では、Readiness changed: の行を出しません

PW-SESSION-FINISH-35

上に積んだ段がある間、pr_restack での載せ直しを warnings で案内し、その段のブランチを消す要求を送りません

PW-SESSION-FINISH-36

PW-SESSION-FINISH-37

PW-SESSION-FINISH-38

base が開発ブランチでない PR を片付けると、その PR の Issue を閉じます

PW-SESSION-FINISH-39

もし待っている Issue の列を書けないなら、warnings に入れて続けます。選択肢の ID が古くて書けないときは、ID を読み直す project_activate の案内を、1 回の実行で 1 回だけ添えます

PW-SESSION-FINISH-41

閉じる対象にすでに閉じた Issue があると、close を送らず、skippedIssues に already-closed で入れます

PW-SESSION-FINISH-42

もし閉じる対象の Issue の種別と状態を読めないなら、warnings に入れ、その Issue を close せず、skippedIssues に failed で入れます

PW-SESSION-FINISH-43

もし対象のリポを含む設定が無いなら、kind が repo-not-in-project の失敗を返します

PW-SESSION-FINISH-44

project に設定の名前を渡して呼ぶと、対象のリポを含む設定が 2 つ以上あっても、その設定を使います
