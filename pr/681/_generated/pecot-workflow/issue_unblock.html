Remove Issue blocker

Remove Issue blocker

issue_unblock

Issue から blocked-by（前提）を外します。

Issue から blocked-by（前提）を外します。

issue_ref は待つ側の Issue で、by は外す前提です。by は別のリポジトリの Issue でもかまいません。

まず、待つ側の Issue の blocked-by を読みます。付いていない前提は外しません。Waits for merge の節に残った古い行も、そのままにします。食い違いは issue_show が warnings で知らせます。前提が付いていなければ、何も書かずに成功を返します。

節に前提の行があるときは、その行を外します。節が空になったときは、見出しごと消します。

節を読めないときは、blocked-by だけを外し、節を直していない旨を warnings で知らせます。外すことが利用者の求めることだからです。

書き込みの後で、待つ側の Issue の判定を読み直して確かめ、issue_block と同じやり方で、列と Status の札を動かします。

Status の札の Needs Attention を Todo に戻すのは、前提が残っているときか、外した前提が閉じていたときだけです。人がほかの理由で付けた札は、開いた最後の前提を外しても外しません。自動処理が人の対応を待って付けた札も、戻しません。

ブランチか PR のある Issue は動かしません。

Issue の依存関係を持つ GitHub Enterprise Server の 3.19 以上が要ります。

参照の短い形の N は、引数 repo の値で補います。その値が無ければ、セッションのディレクトリの git remote で補います。

project で、使うプロジェクトの設定の名前を渡します。省くと、Issue のリポジトリを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

ホストの GitHub トークンが要ります。

使用例

Issue 12 が Issue 11 を待つのをやめます。

{
  "name": "issue_unblock",
  "arguments": {
    "issue_ref": "example-org/my-repo/12",
    "by": "example-org/my-repo/11"
  }
}

外す前提の Issue です。owner/repo/N の形で渡します。別のリポジトリの Issue も指せます。

項目名

型

説明

issue

string

待たせていた側の Issue です。owner/repo/N の形です。

by

string

前提の Issue です。owner/repo/N の形です。

change

"removed" | "unchanged"

blocked-by がどうなったかです。removed（外した）か unchanged（もともと blocked-by ではなかった）です。

moves

array

待つ側の Issue の列か Status を書いたときに、その 1 件を入れる配列です。要素は issue・reason を必ず持ち、列を動かしたときは from・to、Status を書いたときは label も持ちます。書かなかったときは空です。判定を確かめられなかったときと、ボードに書けなかったときも空で、理由は warnings に入ります。

エラーと警告の項目については、共通仕様の出力を参照してください。

エラー名

説明

dependency-rejected

github-auth

other

ほかの名前に当たらない失敗です。MCP のツールでは、コマンドの想定外の例外も含みます。

session-directory-unresolved

MCP のツールだけで起きます。サーバがセッションのディレクトリを決められず、コマンドを動かしません。

前提を外した後で本文の書き込みに失敗したときは、blocked-by は外れたままで、失敗を返します。ボードに書けないときは、blocked-by と本文は残り、warnings に入れるだけです。選択肢の ID が古くて書けないときは、ID を読み直す project_activate の案内を添えます。節かボードに関する warnings だけのときは、成功を返します。

機能要件

次の 22 件の要件を、自動テストで確かめています。

ID

要件

PW-ISSUE-UNBLOCK-01

Issue の参照と by を渡すと、blocked-by から前提を外し、結果の change を removed にします

PW-ISSUE-UNBLOCK-02

付いていない前提を渡すと、何も書き込まずに change を unchanged にし、節に残った古い行も書き換えません

PW-ISSUE-UNBLOCK-03

節に前提の行があるものを外すと、その行を節から消し、節が空になれば節ごと消します

PW-ISSUE-UNBLOCK-04

前提を外した後に判定が変わると、待つ側の Issue の列を動かして、その動きを moves に入れます

PW-ISSUE-UNBLOCK-05

札が Needs Attention で、残りの前提がある、または外した前提が閉じていると、札を Todo へ戻して moves に入れます

PW-ISSUE-UNBLOCK-06

もし外したのが開いた最後の前提なら、札が Needs Attention でも Todo に戻しません

PW-ISSUE-UNBLOCK-07

もし待つ側の Issue に着手の跡があるなら、前提は外して列と札を動かしません

PW-ISSUE-UNBLOCK-09

もし本文の Waits for merge の節が読めないなら、前提だけを外し、節を直していない旨を warnings に入れます

PW-ISSUE-UNBLOCK-10

もし読み直した前提が書いた内容と 2 回続けて合わないなら、列と札を動かさず、その旨を warnings で知らせます

PW-ISSUE-UNBLOCK-11

もし動かす先の値がボードに無いなら、project_init で足し方を案内する文を warnings に入れます

PW-ISSUE-UNBLOCK-12

もし GitHub Enterprise Server が Issue の依存関係に対応しないなら、kind が dependency-rejected の失敗を返します

PW-ISSUE-UNBLOCK-13

もし Issue の参照の形が誤っているなら、kind が invalid-input の失敗を返します

PW-ISSUE-UNBLOCK-14

もしリポジトリがプロジェクトに無いなら、kind が repo-not-in-project の失敗を返します

PW-ISSUE-UNBLOCK-15

もし対象のリポを含む設定が 2 つ以上あり、アクティブなプロジェクトがそのどれも指さないなら、kind が no-active-project の失敗を返します。detail に候補の名前と project の案内を入れます

PW-ISSUE-UNBLOCK-16

もし GitHub API がエラーを返したなら、または本文の書き込みに失敗したなら、失敗を返します

PW-ISSUE-UNBLOCK-17

by でプロジェクトの外のリポジトリの Issue を指すと、プロジェクトに入っているかは待つ側のリポジトリだけ確かめ、前提を外します

PW-ISSUE-UNBLOCK-18

呼ぶと、書いた列と札を moves で返し、書かなかったときは空の moves を返します

PW-ISSUE-UNBLOCK-19

もし列を書けないなら、warnings に入れ、前提を外したまま成功を返します。選択肢の ID が古くて書けないときは、ID を読み直す project_activate の案内を添えます

PW-ISSUE-UNBLOCK-20

もし対象のリポを含む設定が無いなら、kind が repo-not-in-project の失敗を返します

PW-ISSUE-UNBLOCK-21

project に設定の名前を渡して呼ぶと、対象のリポを含む設定が 2 つ以上あっても、その設定を使います

PW-ISSUE-UNBLOCK-22

もし待つ側の札が Needs Attention で、bot が書いた最後の結果のコメントが question・failed・limit のどれかなら、閉じた前提を外しても札を Todo に戻しません

PW-ISSUE-UNBLOCK-23

もし外した後の待つ側の Issue の判定を読めないなら、前提は外したまま列と札を動かさず、判定を出せない旨を warnings に入れて成功を返します
