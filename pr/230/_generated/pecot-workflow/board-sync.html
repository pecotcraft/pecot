Sync board columns

Sync board columns

board_sync

Ready・Blocked・Active・In Review の Issue を、判定に合った列と Status へ動かします。

ボードの全体を読み、Ready・Blocked・Active・In Review にある open の Issue を、判定が求める列と Status へ動かします。

判定・列の移動・Status の書き込みは、ワークフローのほかの部分と同じです（blocked-by・ブランチ・PR を見ます）。

ブランチか PR のある Issue は動かしません。その Issue が blocked のときは、warnings で知らせます。

自動処理が人の対応を待って付けた Needs Attention の札は、Todo に戻しません。自動処理が付けた札かは、Issue に bot が書いた最後の自動処理の結果のコメントで決めます。

Backlog・Pending・Archived にある Issue と、PR のカード・Tracker・Epic は動かしません。

判定を読めない Issue（develop_branch が未設定のときなど）は動かさず、warnings に理由を入れます。

ブランチと PR はボードの一覧に載らないので、Blocked・Active・In Review の Issue は 1 件ずつ読みます。読むのを省くのは、一覧で前提が無いと分かる Ready の Issue だけです。札が Needs Attention で着手の跡の無い Issue は、コメントも読みます。

動かした後で、Archived の項目を、更新の新しい 20 件を残して、ボードから削除します。削除できない Archived の項目は飛ばして続け、最後に失敗を返します。

設定は、project の設定、アクティブなプロジェクト、.pecot/config/projects にある唯一の設定の順で選びます。設定が 2 つ以上あってアクティブなプロジェクトが無いときは、project を求める失敗を返します。

CLI では、実行の前後に GraphQL の rate limit を読み（REST なので点数は減りません）、使った点数と残りの点数を出します。読めないときは、その行を省きます。実行中に rate limit の窓が切り替わったときと、差が負のときは、使った点数の行を省きます。

Issue の依存関係に対応していない GitHub Enterprise Server では、warnings に 1 つ入れ、何も動かしません。

進行の欄がまだ旧い名前（pecot-workflow-<suffix>）なら、同じように Issue を動かします。旧い名前を載せて project_init を案内する警告を、warnings に 1 つ入れます。

Item の値に pecot-priority・pecot-size が残っていれば、残ったフィールドの名前を同じ警告に足します。値の入った Item が無いボードと、値が 10 個を超える Item だけのボードでは、残っていても気づけません。

.pecot/config/projects の下に設定が要ります。アクティブな設定か、project で名前を渡した設定か、唯一の設定を使います。

ホストの GitHub トークンと、プロジェクトを編集する権限が要ります。

使用例

名前を渡した設定のボードを同期します。アクティブなプロジェクトの無いチェックアウトで使います。

{
  "name": "board_sync",
  "arguments": {
    "project": "example-config"
  }
}

引数

project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。

指定:

省略可

型:

string

出力

MCP の結果の項目

項目名

型

説明

moves

array

列か Status を書いた Issue の配列です。要素は issue・reason を必ず持ちます。issue は #N の形で、ホームリポジトリの外は owner/repo#N です。reason は、動かすと決めた Readiness です。from と to は列が変わったときだけ、label は Status を設定したときだけ入ります。

deletedArchived

integer

ボードから削除した Archived の項目の件数です。

エラーと警告の項目については、共通仕様の出力を参照してください。

既に書いた移動と、既に削除した Archived の項目は、そのまま残ります。書き込みの失敗は warnings に入れ、ほかの Issue の同期を続けてから、kind が partial-failure の失敗を返します。Archived の項目を削除できないときも warnings に入れて続け、同じ失敗を返します。この失敗の結果にも、moves と deletedArchived が入ります。判定を読めない Issue があるときと、Issue の依存関係に対応していない GitHub Enterprise Server のときは、成功を返します。

コマンド

GitHub Actions からは、pecot board sync コマンドで呼びます。引数は、次のフラグで渡します。

pecot board sync [options]
--dry-run

ボードへ書き込まず、動かす予定だけを出すかどうかです。

--project

引数 project に当たります。

ボードへ書き込まず、動かす予定を出します。

pecot board sync --dry-run

名前を渡した設定のボードを同期します。アクティブなプロジェクトの無いチェックアウトで使います。

pecot board sync --project example-config

標準出力には何も出しません。

  • 標準エラー: 移動ごとの結果の行（moved）と、Status の書き込みごとの結果の行（set）と、削除した Archived の項目の結果の行（deleted）を出します。--dry-run のときは、代わりに dry-run の行を出します。warning の行を出すのは、次のときです。ブランチか PR のある Issue が blocked のとき。判定を読めない Issue があるとき。書き込みに失敗したとき。Archived の項目を削除できなかったとき。ボードが定義していない値があるとき。GitHub Enterprise Server が Issue の依存関係に対応していないとき。進行の欄が旧い名前のときか、pecot-priority・pecot-size が残っているとき。count の行には、使った GraphQL の点数と残りを出します。rate limit を読んだ後にエラーで止まったときも出します。最後に、書き込みに失敗した Issue の数を error の行で出します。失敗ごとにも error の行を出します。削除できなかった Archived の項目の数も、別の error の行で出します。

機能要件

次の 34 件の要件を、自動テストで確かめています。

ID

要件

PW-BOARD-SYNC-01

呼ぶと、Blocked の Issue の判定が startable か stackable なら、Ready へ動かします

PW-BOARD-SYNC-02

Ready の Issue に済んでいない前提があると、Blocked へ動かします

PW-BOARD-SYNC-03

着手の跡の無い Issue が Active か In Review にあると、判定に合った列（Ready か Blocked）へ戻します

PW-BOARD-SYNC-04

もし着手の跡（ブランチか PR）のある Issue が blocked なら、列と札を変えず、warnings で知らせます。CLI では warning の行を標準エラーに出します

PW-BOARD-SYNC-05

もし前提の無い Blocked の Issue に着手の跡があるなら、Ready へ動かしません

PW-BOARD-SYNC-06

Backlog・Pending・Archived の間、その Issue の前提を読まず、列と札を動かしません

PW-BOARD-SYNC-07

前提がマージされずに閉じると、待っていた Issue の札を Needs Attention にします

PW-BOARD-SYNC-08

札が Needs Attention の Issue の前提がすべて済むと、札を Todo に戻します

PW-BOARD-SYNC-09

CLI で --dry-run を付けて打つと、ボードに書かず、動かす予定を dry-run の行で標準エラーに出します

PW-BOARD-SYNC-10

もし書き込みに失敗した Issue があるなら、warnings に入れてほかの Issue を続け、最後に kind が partial-failure の失敗を返します。CLI では終了コード 1 で終わります。選択肢の ID が古くて書けないときは、ID を読み直す project_activate の案内を、1 回の実行で 1 回だけ添えます

PW-BOARD-SYNC-11

一覧で前提が 0 件の Ready の Issue があると、前提を個別に読みません。Blocked・Active・In Review の Issue は、前提の件数によらず個別に読みます

PW-BOARD-SYNC-12

もし動かす先の値がボードに無いなら、その Issue を動かさず、warnings に 1 つ入れます

PW-BOARD-SYNC-13

もし GitHub Enterprise Server が Issue の依存関係に対応しないなら、warnings に 1 つ入れ、何も動かさずに成功を返します

PW-BOARD-SYNC-14

CLI で打つと、実行の前後の GraphQL の点数から、使用量と残りを count の行で標準エラーに出します。差が負か、点数の窓が途中で切り替わったときは、使用量の行を省きます

PW-BOARD-SYNC-15

もし CLI で点数を読めないなら、count の行を出さずに続けます

PW-BOARD-SYNC-16

もしボードの取得で GitHub API がエラーを返したなら、失敗を返します。CLI では、点数の行を出して、終了コード 1 で終わります

PW-BOARD-SYNC-17

アクティブなプロジェクトが無く、設定がちょうど 1 つの間、その設定を使います

PW-BOARD-SYNC-18

もしアクティブなプロジェクトが無く、設定が 2 つ以上あるなら、project を求める detail を入れて、kind が no-active-project の失敗を返します

PW-BOARD-SYNC-19

project に設定の名前を渡して呼ぶと、アクティブな設定ではなく、その設定を使います

PW-BOARD-SYNC-20

もし project の設定が無いなら、使える設定の名前を detail に入れて、kind が project-not-found の失敗を返します

PW-BOARD-SYNC-21

もし設定が 1 つも無いなら、kind が no-active-project の失敗を返します

PW-BOARD-SYNC-22

一覧の新しいクエリがスキーマの失敗になると、古いクエリで読み直し、前提を読まずに成功を返します

PW-BOARD-SYNC-23

もし判定を読めない Issue があるなら、理由を warnings に入れ、その Issue を動かしません

PW-BOARD-SYNC-24

Ready の Issue の前提が輪になると、Blocked へ動かします

PW-BOARD-SYNC-25

もしカードが PR・Tracker・Epic なら、列と札を動かしません

PW-BOARD-SYNC-26

設定で先頭にないリポジトリの Issue を動かすと、moves の issue を owner/repo#N の形で表します

PW-BOARD-SYNC-27

もし設定のファイルが JSON として読めないなら、kind が config-invalid の失敗を返します

PW-BOARD-SYNC-28

更新の新しい 20 件を超える Archived の項目があると、超えた分だけをボードから削除し、件数を deletedArchived に入れます

PW-BOARD-SYNC-29

CLI で --dry-run を付けて打つと、Archived の項目を削除せず、dry-run: would delete N archived items の行を標準エラーに出します

PW-BOARD-SYNC-30

もし Archived の項目を削除できなかったなら、warnings に入れて続けます

PW-BOARD-SYNC-31

もし Archived の項目を削除できなかったなら、kind が partial-failure の失敗を返し、削除できなかった件数を detail に入れます。CLI では、最後に error: could not delete N archived items from the board の行を出し、終了コード 1 で終わります

PW-BOARD-SYNC-32

もし札が Needs Attention で、bot が書いた最後の結果のコメントが question・failed・limit のどれかなら、前提がすべて済んでも札を Todo に戻しません

PW-BOARD-SYNC-33

進行の欄が旧い名前（pecot-workflow-<suffix>）である間、同じ Issue を動かし、project_init を案内する警告を warnings に 1 つ入れます

PW-BOARD-SYNC-34

Item の値に pecot-priority・pecot-size が残っている間、同じ Issue を動かし、残ったフィールドの名前を project_init を案内する警告に足します。進行の欄の警告と合わせて、警告は 1 つです
