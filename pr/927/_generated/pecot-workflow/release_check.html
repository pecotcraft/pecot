Check release

Check release

release_check

github-ops の release-create に渡す値を、リリースの前に pecot の決まりに照らします。GitHub API を呼ばず、手元の git と git の remote を読みます。

値を受けて、決まりに外れた所を problems に返します。GitHub API を呼ばず、何も書きません。

reads の code scanning・secret scanning に open の alert があると、blocking-alert の項目にします。

open の Dependabot alert は warnings に入れて知らせ、リリースを止めません。alert ごとの #<number>・パッケージ・severity と、一覧の URL を並べます。

機能が無効のリポジトリでは、その種類の確認を飛ばして skipped に入れます。code scanning の解析がまだ無いときは、alert が 0 件とみなします。

alert の一覧を渡していないか、読めなかったか、最後のページに続きがあると、alerts-unread の項目にします。

リリースの種類が nx のリポジトリでは、alert だけを見ます。params は受け付けません。

nx でないリポジトリでは、タグの形・CHANGELOG の節・リリースの名前・タグの有無・sha・前のリリースからのコミットを見ます。

タグは v<version> です。packages を設定したリポジトリでは、登録したパッケージの名前を接頭辞にした <package>-v<version> です。

body は、CHANGELOG のその版の節と同じでなければなりません。前後の空白は比べません。

CHANGELOG は、設定ファイルにあるリポジトリの changelog_file か、パッケージの changelog です。無いときは git のルートの CHANGELOG.md で、その次が AIST-CHANGELOG.md です。

リリースの名前は、name を省くとタグです。monorepo では <package> v<version> です。

タグが手元・remote・GitHub のリリースのどれかにあると、tag-exists の項目にします。

sha は、remote の <release_branch> の先頭でなければなりません。remote は origin で、origin が無ければ最初の remote です。

前のリリースのタグから sha までのコミットを、手元の git で数えます。前のタグが無いときは数えません。git fetch はせず、手元の ref も動かしません。

リポジトリは、引数 repo から決めます。無ければ remote の origin から、origin も無ければ最初の remote から決めます。

repo が今の git remote と食い違うときは、repo を使います。warnings には using repo <owner/repo> (current Git remote: <owner/repo>) が入ります。

remote の URL から owner/repo を読めないときは、repo と比べません。repo があれば、repo を使い、warnings に using repo <owner/repo> で始まる文を入れます。文の末尾は (could not read the repository from the URL of the Git remote <name>) です。無ければ失敗を返し、detail が the repository is ambiguous で始まります。理由と repo の案内が続きます。

外れた所が無ければ、成功の結果の文は ok です。あれば、最初の外れた所の <引数>: <内容> です。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

セッションのディレクトリは、git のリポジトリの中でなければなりません。remote の origin（無ければ最初の remote）は、タグとリリースブランチの確認に使います。

設定ファイルに、リポジトリの release_branch が要ります（project_link で設定します）。リリースの種類が nx のときは要りません。

使用例

reads に 3 種類の alert の一覧と get_release_by_tag の結果を渡し、release-create に渡す値を照らします。

{
  "name": "release_check",
  "arguments": {
    "params": {
      "tag": "v0.6.1",
      "sha": "3f2c1e0",
      "body": "### Fixed"
    }
  }
}

リリースの種類が nx のリポジトリで、reads の alert だけを照らします。

{
  "name": "release_check",
  "arguments": {}
}

引数

params

github-ops の release-create の params です。tag・sha・body・name を持ちます。リリースの種類が nx のリポジトリでは省きます。

指定:

省略可

型:

object

project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

指定:

省略可

型:

string

reads

公式の MCP の読み取りの結果です。open の alert の一覧を 3 種類と、params のタグの get_release_by_tag の結果を渡します。

指定:

省略可

型:

object

出力

MCP の結果の項目

項目名

型

説明

problems

array

決まりに外れた所の配列です。要素は field・code・message を必ず持ちます。受け付ける値が決まっているときは candidates に入れます。空なら、params をそのまま release-create に渡せます。

skipped

array

機能が無効なので飛ばした確認の文の配列です。例は Dependabot alerts (feature disabled) です。飛ばした確認が無ければ空です。

dependabotAlerts

object

Dependabot アラートの状態です。読めなかったときは入りません。enabled・openCount・alertsUrl を必ず持ち、maxSeverity は、開いたアラートがあるときだけ入ります。

version

string

params のタグの版です。タグを読めないときと、リリースの種類が nx のときは入りません。

releaseNotes

string

CHANGELOG のその版の節で、リリースの本文にする文です。読めないときは入りません。

commitCount

integer

前のリリースのタグから sha までのコミットの数です。前のタグが無いときは入りません。

エラーと警告の項目については、共通仕様の出力を参照してください。

エラー

エラー名

説明

git-unresolved

git のリポジトリのルートが見つからないか、remote のタグかブランチを読めません。repo を省いて git remote から owner/repo を読めないときと、git の外で repo を省いたときも含みます。repo を省いて remote の URL から owner/repo を読めないときは、detail が the repository is ambiguous で始まります。理由と repo の案内が続きます。

no-active-project

対象のリポを含むプロジェクトの設定が 2 つ以上あり、使う設定が決まりません。アクティブなプロジェクトが候補を指さず、project もありません。

repo-not-in-project

対象のリポを含むプロジェクトの設定がありません。project で選んだ設定が対象のリポを含まないときも含みます。

project-not-found

project の名前の設定がありません。

repo-setting-missing

nx でないリポジトリで、release_branch が未設定です。

github-mcp-shape

reads に渡した値が、公式の GitHub MCP の結果の形と違います。

invalid-input

引数の形が誤っています。

project-root-not-found

プロジェクトのルートを決められません。

other

ほかの名前に当たらない失敗です。ツールの想定外の例外も含みます。

session-directory-unresolved

サーバがセッションのディレクトリを決められず、ツールを動かしません。

機能要件

次の 23 件の要件を、自動テストで確かめています。

ID

要件

PW-RELEASE-CHECK-01

決まりに合う params と読み取りの結果を渡すと、空の problems と、version・releaseNotes・commitCount を返します

PW-RELEASE-CHECK-02

もしタグが v<version> の形でないなら、tag-name の項目に期待するタグの候補を添えます

PW-RELEASE-CHECK-03

packages を設定したリポジトリでは、パッケージ名を接頭辞にしたタグと、そのパッケージの CHANGELOG で照らします

PW-RELEASE-CHECK-04

もし CHANGELOG か、その中の版の節が無いなら、changelog-missing の項目を返します

PW-RELEASE-CHECK-05

もし body がリリースノート（releaseNotes）と違うなら、リリースノートを候補に添えた body-mismatch の項目を返します。前後の空白は比べません

PW-RELEASE-CHECK-06

もしリリースの名前が期待する名前と違うなら、release-name の項目を返します。name を省くと、タグを名前とみなします

PW-RELEASE-CHECK-07

もしタグが手元・remote・GitHub のリリースのどれかにあるなら、tag-exists の項目を返します

PW-RELEASE-CHECK-08

もし sha が remote の <release_branch> の先頭でないか、ブランチが remote に無いなら、sha-mismatch の項目を返します

PW-RELEASE-CHECK-09

もし sha のコミットが手元に無いなら、not-found の項目を返します

PW-RELEASE-CHECK-10

もし前のリリースのタグから sha までにコミットが無いなら、no-commits の項目を返します。前のタグが無いときは commitCount を入れません

PW-RELEASE-CHECK-11

もし open の code scanning か secret scanning の alert があるなら、番号と URL を添えた blocking-alert の項目を返します

PW-RELEASE-CHECK-12

open の Dependabot alert があるか一覧を読めないと、止めずに warnings で知らせ、状態を dependabotAlerts に入れます

PW-RELEASE-CHECK-13

機能が無効の間、その種類の確認を飛ばして skipped に入れます

PW-RELEASE-CHECK-14

もし alert の一覧が無いか、読めないか、最後のページに続きがあるなら、alerts-unread の項目を返します。code scanning の解析がまだ無いときは 0 件とみなします

PW-RELEASE-CHECK-15

もし reads.release が無いか、404 でない誤りなら、read-required の項目で get_release_by_tag の読み方を案内します

PW-RELEASE-CHECK-16

リリースの種類が nx のリポジトリで呼ばれると、alert だけを照らします。params を渡すと、unexpected の項目を返します

PW-RELEASE-CHECK-17

もし nx でないリポジトリで params を省いたなら、required の項目と alert の結果を返します

PW-RELEASE-CHECK-18

もし release_branch を設定していないなら、設定の仕方を案内して kind が repo-setting-missing の失敗を返します

PW-RELEASE-CHECK-19

もし reads の値が公式の MCP の結果の形でないなら、kind が github-mcp-shape の失敗を返します

PW-RELEASE-CHECK-20

もし git のルートか、remote のタグか、repo を省いたときの remote のリポジトリを読めないなら、kind が git-unresolved の失敗を返します

PW-RELEASE-CHECK-21

もし repo が git remote と食い違うか remote の URL から読めないなら、warnings に入れて repo を使います。repo も無いときは失敗を返します

PW-RELEASE-CHECK-22

対象のリポを含む設定が無いか、決まらないと失敗を返します。project で設定の名前を渡すと、その設定を使います

PW-RELEASE-CHECK-23

常に、リリースノートからは、版の節の本文が使わないリンクと脚注の定義を除きます。ただし、リストや引用の中の定義は残します。節の外にある、本文が使う定義は、本文の末尾に加えます
