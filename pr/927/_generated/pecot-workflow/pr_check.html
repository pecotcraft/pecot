Check pull request

Check pull request

pr_check

公式の MCP の create_pull_request・update_pull_request・merge_pull_request に渡す値を、書く前に pecot の決まりに照らします。GitHub を読み書きしません。

値を受けて、決まりに外れた所を problems に返します。GitHub を読み書きしません。読み取りが要る決まりは、reads の結果で照らします。

同梱のテンプレートを指すと、本文をテンプレートの見出しと書き方に照らします。テンプレートの先頭の案内のコメントと frontmatter が本文に残っていれば、それも返します。

差し替えたテンプレートを指すときと、テンプレートを省くときは、本文に見出しの決まりを当てません。

create では title・head・base が要ります。update では pullNumber と、その PR の reads.pull_request が要ります。update で省いた title・base は、reads.pull_request の値で照らします。

本文が Issue を閉じず（GitHub が認める 9 つの語か owner/repo#N）、ブランチの名前に Issue の番号があれば、reads.issue でその Issue を見ます。Epic でなければ、Closes #N を候補に missing-closes を返します。

番号の空いた Closes # の行が本文に残っていれば、empty-closes を返します。

同梱の create のテンプレートで、Summary に画像が無く screenshot も空なら、screenshot の項目を返します。

head が今のブランチなら、作業ディレクトリの .pecot/state/.pecot-base を読みます。スタックの記録があれば、reads.pull_requests の親 PR から base を決めます。親 PR が開いていれば親ブランチ、マージ済みなら開発ブランチです。

スタックの記録が無ければ、base は開発ブランチです。head が今のブランチでなく、記録を読めないときは、base を照らしません。

リリース PR は、base を release_branch に照らし、Issue・画像・題の scope を見ません。リリース PR とは、同梱の release のテンプレートの PR か、開発ブランチから release_branch への PR です。

nx を使うリポでは、題の scope を、変更した nx のプロジェクトの scope と比べます。nx のプロジェクトか差分を読めないときは、題の scope を照らさず、warnings に入れます。

create では、push していないか remote とずれたブランチ、変更したファイル、stash の項目を返します。スタックして remote とずれたブランチの直し方は、親 PR と remote の先頭から決めます。

merge では、reads.pull_request の PR が開いていて、下書きでなく、衝突していないことを照らします。expectedHeadSha が PR の先頭と違えば、head-moved を返します。

merge で base が開発ブランチでも release_branch でもなければ、reads.pull_requests を見ます。base を head に持つ開いた PR が無いことを照らします。

merge の方法は、リリース PR が merge、ほかが squash です。merge_method を省くと、GitHub は merge でマージします。

project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

外れた所が無ければ、成功の結果の文は ok です。あれば、最初の外れた所の <引数>: <内容> です。

使用例

本文と base と題を照らし、外れた所を problems に返します。

{
  "name": "pr_check",
  "arguments": {
    "method": "create",
    "owner": "acme",
    "repo": "demo",
    "title": "feat(demo): #12 見本の変更",
    "head": "feat/demo/12",
    "base": "main",
    "template": "pecot-template://pr/create",
    "body": "## Summary"
  }
}

reads.pull_request の PR をマージしてよいかを照らします。

{
  "name": "pr_check",
  "arguments": {
    "method": "merge",
    "owner": "acme",
    "repo": "demo",
    "pullNumber": 21,
    "merge_method": "squash",
    "expectedHeadSha": "0123456789abcdef0123456789abcdef01234567"
  }
}

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

出力

MCP の結果の項目

項目名

型

説明

problems

array

決まりに外れた所の配列です。要素は field・code・message を必ず持ちます。受け付ける値が決まっているときは candidates に入れます。空なら、値をそのまま書けます。

エラーと警告の項目については、共通仕様の出力を参照してください。

エラー

エラー名

説明

github-mcp-shape

reads に渡した値が、公式の GitHub MCP のツールの結果の形と違います。

git-unresolved

create で、作業ディレクトリが git のリポジトリでないか、remote か今のブランチを決められません。base の記録の位置が head の履歴に無いときも含みます。

content-invalid

base の記録の形が誤っています。

repo-setting-missing

develop_branch が未設定です。リリース PR では release_branch が未設定のときです。

invalid-input

引数の形が誤っています。method が create・update・merge でないときを含みます。

project-root-not-found

プロジェクトのルートを決められません。

other

ほかの名前に当たらない失敗です。ツールの想定外の例外も含みます。

session-directory-unresolved

サーバがセッションのディレクトリを決められず、ツールを動かしません。
