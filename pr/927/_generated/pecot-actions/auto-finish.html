auto finish

auto finish

自動処理の実行を終えます。結果を決めて Issue に結果のコメントを書き、待ちの Status を書き、起動ラベルを外します。

自動処理の job の最後の step（if: always()）が、job-status・start-outcome・result-file・execution-file を渡して呼びます。setup job は、決めた結果を result と body-file で渡して呼びます。

result の無いときは、上から順に見て、最初に当たったもので結果を決めます。

start-outcome が success でなければ、setup-missing にします。本文には、Start の step が成功しなかったことを書きます。

result-file のファイルがあれば、frontmatter の result を結果とし、本文をコメントに足します。本文の先頭の HTML コメントは除きます。frontmatter が無いか、result が決まった値でなければ、warning の行を出し、読めなかった理由を本文にして failed にします。

ファイルが無く、job が success なら、スキルが結果を書かずに終わったことを本文にして failed にします。

ファイルが無く、job が cancelled なら limit にします。failure なら、execution-file の最後の result の行が error_max_turns のとき limit に、ほかは failed にします。

結果が question・failed・limit のときは、コメントを書き、既定の Status（fields.status）を Needs Attention にし、起動ラベルを外します。

結果が pr-created・out-of-scope・setup-missing のときは、コメントを書き、起動ラベルを外します。Status は書きません。

結果が ci-passed・ci-fix-pushed のときは、コメントだけを書きます。

本文の先頭に、結果・GITHUB_RUN_ID・GITHUB_RUN_ATTEMPT・ブランチを入れた、画面に出ない目印の行を付けます。ブランチは、Issue に紐づく開いた PR の head です。PR が無ければ、Development のブランチのうち、末尾が Issue の番号のものです。

同じ目印を持つ bot のコメントがあれば、コメントを書きません。起動ラベルが残っていれば外し、結果が待ちの Status を書くものなら、Status も書き直します。

Issue がボードに無いか、Status に Needs Attention の選択肢が無いときは、足りない設定をコメントに書き、Status を変えずに step を成功にします。

外す起動ラベルの名前は、PECOT_AUTO_LABEL から読みます。無ければ pecot-auto です。ラベルが既に外れていても、失敗にしません。

プロジェクトの設定に fields.status が要ります。

本文は、テンプレート auto-result を埋めて作ります。トークンの値と secret の値を書きません。

リポジトリを checkout した後の step で呼びます。

対象のリポを含み、fields.status を持つプロジェクトの設定が要ります。

Issue とプロジェクトを編集する権限を持つ GitHub トークンが要ります。

使用例

自動処理の job の最後に、結果を決めてコメントを書きます。

- uses: pecotcraft/pecot/actions/auto-finish@<ref>
  with:
    token: ${{ steps.app-token.outputs.token }}
    issue: ${{ needs.gate.outputs.number }}
    job-status: ${{ job.status }}
    start-outcome: ${{ steps.start.outcome }}
    result-file: ${{ runner.temp }}/pecot-auto/result.md
    execution-file: ${{ steps.claude.outputs.execution_file }}

setup job で、足りない設定を書いた本文の setup-missing を書きます。

- uses: pecotcraft/pecot/actions/auto-finish@<ref>
  with:
    token: ${{ steps.app-token.outputs.token }}
    issue: ${{ needs.gate.outputs.number }}
    result: setup-missing
    body-file: ${{ steps.check.outputs.body-file }}

入力

  • result・job-status は、同時に指定できません。

  • result・start-outcome は、同時に指定できません。

  • result・result-file は、同時に指定できません。

  • result・execution-file は、同時に指定できません。

  • body-file を指定するときは、result も指定します。

issue

Issue の参照です。ワークフローのリポジトリの Issue の番号か、owner/repo/N で渡します。 番号だけの形は、GITHUB_REPOSITORY のリポジトリで補います。

指定:

必須

型:

string

body-file

result のときの、コメントに足す文を書いたファイルのパスです。

指定:

省略可

型:

string

execution-file

claude-code-action の出力 execution_file のパスです。省いても、空でもかまいません。

指定:

省略可

型:

string

job-status

job の終わり方（job.status）です。success・failure・cancelled のどれかです。result の無いときに要ります。

指定:

省略可

型:

string

project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、Issue のリポジトリを含む設定を使います。

指定:

省略可

型:

string

result

決めた結果をそのまま書くときの結果です。setup job が setup-missing を渡します。pr-created・ci-passed・ci-fix-pushed・question・out-of-scope・failed・limit・setup-missing のどれかです。

指定:

省略可

型:

string

result-file

スキルが書く結果のファイルのパスです。結果は frontmatter の result に、コメントに足す文は本文に書きます。ファイルが無ければ、スキルが結果を書かなかったとみなします。

指定:

省略可

型:

string

start-outcome

auto-start の step の終わり方（steps.<id>.outcome）です。result の無いときに要ります。

指定:

省略可

型:

string

token

コメント・ボード・ラベルを書く GitHub トークンです。ワークフローの App のトークンを渡します。

指定:

省略可

型:

string

出力

  • 標準エラー: 実行のログに、書いたコメントの URL の行と、書いたものを created・set・removed の行で出します。書かなかったときは、理由を添えた skipped の行を出します。起動ラベルが既に外れていたときは unchanged の行を、Status を書けないときと結果のファイルを読めないときは warning の行を出します。本文がテンプレートに合わないときは、error の行を出します。

エラー

エラー名

説明

invalid-input

result と、job-status・start-outcome・result-file・execution-file のどれかを一緒に渡しました。result の無いときに job-status か start-outcome が無いとき、result の無い body-file、無い body-file のファイルも同じです。step は失敗になります。

invalid-input

issue の形が誤っているか、result・job-status・start-outcome が決まった値でありません。step は失敗になります。

not-initialized

プロジェクトの設定に fields.status がありません。step は失敗になります。

content-invalid

埋めた本文がテンプレートに合いません。何も書かずに step を失敗にします。

no-active-project

対象のリポを含むプロジェクトの設定が 2 つ以上あり、使う設定が決まりません。アクティブなプロジェクトが候補を指さず、project もありません。step は失敗になります。

project-not-found

project の名前の設定がありません。step は失敗になります。

repo-not-in-project

リポジトリがプロジェクトにありません。step は失敗になります。

github-auth

GitHub トークンが見つからないか、GitHub がトークンを拒みました。step は失敗になります。

github-not-found

GitHub に対象が見つかりません。step は失敗になります。

github-rate-limit

GitHub API のレート制限に当たりました。step は失敗になります。

github-api

GitHub API がほかのエラーを返しました。step は失敗になります。

project-root-not-found

プロジェクトのルートを決められません。step は失敗になります。

other

ほかの名前に当たらない失敗です。step は失敗になります。

コメントを書く前に止まったときは、Issue に何も残りません。コメントの後で Status かラベルの書き込みに失敗したときは、同じ run を再実行せずに step を呼び直すと、同じ実行の目印を見て、コメントを重ねずに書き直します。

機能要件

次の 16 件の要件を、自動テストで確かめています。

ID

要件

PA-AUTO-FINISH-01

結果が question・failed・limit だと、結果のコメントを書き、Status を Needs Attention にして、起動ラベルを外します。コメントの URL を実行のログに出します

PA-AUTO-FINISH-02

結果が pr-created・out-of-scope・setup-missing・ci-passed・ci-fix-pushed だと、Status を書きません。ci-passed・ci-fix-pushed では、起動ラベルを残します

PA-AUTO-FINISH-03

もし起動ラベルが既に外れているなら、unchanged の行を出して step を成功にします

PA-AUTO-FINISH-04

PECOT_AUTO_LABEL がある間、その名前のラベルを起動ラベルとして外します

PA-AUTO-FINISH-05

もし Issue がボードに無いか、Status に Needs Attention の選択肢が無いなら、Status を書きません。足りない設定をコメントに書き、warning の行を出して step を成功にします

PA-AUTO-FINISH-06

もし result-file のファイルが無く、job が success なら、スキルが結果を書かずに終わったことを本文にして failed を書きます

PA-AUTO-FINISH-07

もし result-file のファイルが無く、job が cancelled か、実行のファイルの最後の result が error_max_turns なら、limit を書きます。ほかの失敗では failed を書きます

PA-AUTO-FINISH-08

もし同じ実行・同じ試行の目印を持つ bot のコメントがあるなら、コメントを書きません。Status と起動ラベルを書き直し、skipped の行を出します

PA-AUTO-FINISH-09

GITHUB_RUN_ID が無い間、目印を付けず、Issue のコメントを読みません

PA-AUTO-FINISH-10

もし result と job から決める入力を一緒に渡したか、result の無いときに job-status か start-outcome が無いなら、何も読まずに step を失敗にします。無い body-file のファイルも同じです

PA-AUTO-FINISH-11

もし start-outcome が success でないなら、結果のファイルがあっても、Start の step の失敗を本文にして setup-missing を書きます

PA-AUTO-FINISH-12

もしプロジェクトの設定に fields.status が無いなら、何も読まずに、project init を案内して step を失敗にします

PA-AUTO-FINISH-13

start-outcome が success で result-file のファイルがあると、job の終わり方にかかわらず、frontmatter の result と本文をそのまま書きます

PA-AUTO-FINISH-14

もし結果のファイルに frontmatter が無いか、result が決まった値でないなら、warning の行を出し、読めなかった理由を本文にして failed を書きます

PA-AUTO-FINISH-15

常に、トークンの値を、実行のログとコメントに書きません

PA-AUTO-FINISH-16

Issue に紐づく開いた PR があると、目印のブランチに、その PR の head を書きます
