# 手順書型プレゼンのアウトライン設計ガイド

手順書型プレゼンには 2 系統ある。画面操作手順は、素材がスクリーンショットで、画像に印とステップを重ねるレイアウトを使う。CLI 実行手順は、素材が実行したコマンドと出力のテキストで、端末の画面に印とステップを重ねるレイアウトを使う（スクリーンショットは要らない）。系統は工程（ページ）単位で選び、1 プレゼン内で混在してよい。

レイアウトの名前は、`slide_theme` の `data.layouts[].description` から選ぶ。この文書には書かない。
該当するレイアウトが無いテーマでは、手順書型に向かないことをユーザーに伝え、使うテーマを確認する。

どちらの系統でも、素材に無い操作・確認事項は書けない。不足・不明は推測で補わず、ユーザーに確認する。

既定は、画像に印とステップを重ねるレイアウト。端末の画面に重ねるレイアウトを選ぶのは、ローカル PC のターミナルを使う操作だけ（SSH でリモートに入る工程も、ローカル PC のターミナルで操作するなら含む）。
次のものは、スクリーンショットと画像のレイアウトで扱う。ブラウザ上のターミナル（SSM セッションマネージャー等）。TUI の画面描画。GUI が混在する画面。色や罫線が意味を持つ出力。端末のレイアウトの `text_constraints` に収まらない出力。

## 1. 素材を受け取る

両系統に共通:

- 操作の流れがわかる情報（実施メモ、またはユーザーの説明）
- 読者に参照させる元資料・前提手順の URL（あれば）

画面操作手順では、実施時のスクリーンショット一式を受け取る。

CLI 実行手順では、実際に実行したコマンド列とその出力を受け取る。ログは全文を受領してよいが、スライドに残すのは説明に必要な行だけ。カレントディレクトリが変わる工程はプロンプト表記も受領する。実行していないコマンドの出力は書けない。実ログが無ければユーザーに提出を求める。

## 2. 素材を工程に区切る

- 素材を実施の流れ順に並べ、作業の意味の切れ目で工程に区切る。枚数や steps 数で割らない
- **1 工程 = 1 ページ**。受領した確認事項のうち画面上で観測できるものを checks に割り付け、観測できない確認事項は notes に回す
- 画面操作手順は **1 画面操作 = 1 step**。step ごとに画像を差し替えるのが既定。画面が変わらない例外のときだけ同じスクリーンショットを使い回し、マーカー位置だけ変える
- CLI 実行手順は **1 コマンド実行 = 1 step**。同じ画面に出力が積み上がる流れを基本とする。terminalContent に工程分の入出力を置き、step ごとにマーカーを該当行へ送る。step ごとに terminal を丸ごと差し替えて、画面を作り直さない
- 操作説明が text_constraints に収まらないときは、ステップや工程の切れ目で組み替える。定義は、テーマの `references/` にある、それぞれのレイアウトの yaml に書かれている（`slide_page` の応答にも載る）。talk-dir の `references/` に同名の yaml があれば、そちらが優先される。
- 概念説明や判断材料のページが要りそうになったら別目的の混入。削るか別プレゼンに分ける

## 3. 骨格に配置する

```text
表紙 → 目次 → （章扉 → 手順ページ×N）× M → （参考リンク →） 裏表紙
```

各ページのレイアウトは、`data.categories` の `fixed`（表紙・目次・章扉・参考・裏表紙）から選ぶ。

- テーマ（対象システム・工程系列）がひとつなら章扉を省略し、複数ならテーマごとに章扉で区切る
- 目次の items は手順ページと 1:1。`description:` に要約・担当注記、`slideNumber:` で該当ページへ
- 元資料・前提手順があれば参考リンクのページを裏表紙の直前に置く。カードの `description` には「何が確認できて、本手順とどう関係するか」を書く

手順ページの `title` / `titleContent.label` と目次の `section` の割付は次のとおり。props の名前は、選んだレイアウトの yaml に従う。

| フィールド | 内容 | 例 |
|---|---|---|
| `title` | 工程名 | AWSアクセスポータルへのログイン |
| `titleContent.label` | STEP 通し番号（テーマが複数なら接頭辞込み） | STEP 1 / BE STEP1 |
| 目次の `section` | STEP 番号＋工程名 | BE STEP1 libにソース更新をマージ |

目次のレイアウトの yaml にある「section 名は title と完全一致させる」より本表を優先する。系統が混在しても STEP 通し番号は系統を跨いで連番を維持する。

## 4. 実装へ引き渡す

画面操作手順では、スクリーンショットを場面を表す英語名で命名し、数字で始めない（連番はスライドを入れ替えると実態からずれる）。例: `lib-circleci-success.png`。
名前が衝突するときはテーマ接頭辞など記述的な語で区別する。格納先・参照パスは implementation-guide.md「スライド固有アセット」に従う。
ページ × 工程 × 使用スクリーンショットの割付が確定したら `implementation-guide.md` に進む。

CLI 実行手順では、ページ × 工程 × コマンド列と出力行・プロンプト表記の割付を確定してから `implementation-guide.md` に進む。`public/slides/images/` に置くアセットは無い。
