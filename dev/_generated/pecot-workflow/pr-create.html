Create PR

pr_create

PR（プルリクエスト）を作ります。

モードは、prepare・file・message の 3 つです。

複数のモードを渡すと、prepare が file より優先され、file が message より優先されます。

template は、default か release です。

prepare では、テンプレートを .pecot/tmp/output/ にコピーし、そのパスを返します。

prepare と default のテンプレートでは、コピーの base をリポジトリの develop_branch にします。

積んで着手した記録 .pecot/state/.pecot-base があると、base は develop_branch ではなく、記録の base（下の段のブランチ）です。今のブランチの default のテンプレートだけが対象です。head の引数・フロントマターの head・release のテンプレートでは、記録を読みません。

作業ディレクトリの worktree に .pecot/state/.pecot-base が無いときは、積んだ先を求めます。作業中の Issue の判定が stackable で、判定の示すブランチの変更をブランチが持てば、そのブランチに積んだものとします。変更を持つとは、同じコミットか、そのブランチを載せ直した後の同じ patch を持つことです。そのブランチが自分のコミットを持たなければ、その先頭がブランチの祖先であることです。

そうでなければ、開発ブランチからの着手とします。判定を読めないか blocked のときと、GitHub に届かないとき、追跡参照が無いときは、cannot infer the stacked base の文を warnings に入れます。求めた結果は書きません。

記録があるときの prepare は、通信せずに、コピーの base を記録の base にします。記録が無ければ、作業中の Issue の判定を読んで base を求めます。

積んだ先を求められないとき、投稿は失敗を返し、PR を作りません。開発ブランチ向けの PR に、下の段の差分が入りうるためです。dry_run と prepare は、warnings に入れて続けます。

下の段の PR が開いているときは、その base で PR を作ります。渡した base が develop_branch なら、kind が content-invalid の失敗を返します。

下の段の PR がマージ済みのときは、develop_branch を base にして PR を作ります。

下の段の PR は、開いている・マージ済み・閉じた、の順に選びます。

下の段の PR が無く、マージもされていないときは、PR を作りません。base ブランチに開いた PR が無いと書いた detail を入れて、kind が pr-state の失敗を返します。

記録の形が誤っているときは、base を決められないので、kind が content-invalid の失敗を返します。

記録のコミットが head の履歴に無いときは、file と message の投稿では PR を作らず、失敗を返します。このとき、下の段の PR と remote の先頭を読み、pr_restack と同じ判断で載せ直し済みかを決めます。載せ直し済みと決まったときだけ、detail の 2 行目で pr_restack で記録を書き直すことを案内します。最後の行で、記録を書いたブランチで呼ぶか、head を渡して記録なしで作るかを案内します。prepare では確かめません。

積んだ base の PR を作った後、下の段のスタックに登録します。スタックが無ければ、2 つの PR で新しく作ります。下の段の PR がスタックの一番上に無いときは、追加を呼ばず、そのことを warnings に入れます。スタックの API が無いリポジトリと接続の失敗では、URL を添えて warnings に入れ、PR は残します。

PR を作った後、head ブランチが指す Issue を待っている Issue を読み、判定に従って列を動かします。読むのは、選んだプロジェクトのボードの項目だけで、ボードに載っていない Issue は飛ばします。判定に作った PR が出ていないときは、約 1.5 秒待ってから 1 回だけ読み直します。着手の跡がある Issue は動かしません。

接続の失敗を含め、この処理の失敗は warnings に入れるだけで、成功と失敗を変えません。状態を確かめられないときは、could not confirm that GitHub reflects PR #<N> ... の文を入れ、後から board_sync で列を直せると添えます。head の番号の Issue が PR のリポジトリに無いときは、何も入れずに飛ばします。dry_run とリリースの PR では行いません。

nx のリポジトリの prepare では、期待する題の scope を、題の行にコメントとして足します。

prepare と default のテンプレートでは、末尾の Closes # に、作業中の Issue の番号を入れます。作業中の Issue は、git remote と今のブランチ名の末尾の番号から求めます。古い版の .pecot/state/.pecot-active が残っていても読まないので、.pecot/state/ の無い clone でも同じ Closes が入ります。

その Issue が Epic のときは、コピーの Closes # を空のままにします。

file では、リポジトリ・base・題・head・draft をフロントマターで決めます。同じ名前の引数は無視します。

message では、リポジトリは repo です。repo を省くと、プロジェクトの設定にあるリポジトリを指す remote のリポジトリです。remote は origin を先に見て、次に git remote の順で見ます。

本文が head ブランチ名の末尾の番号 N に触れていないと、本文に Closes #N を足します。テンプレートが release のときと、no_issue_ref を付けたときは足しません。

file では、その Issue が Epic のときは Closes を足しません。

題・本文・base を確かめ、次のどれかが誤っていると、kind が content-invalid の失敗を返します。Issue の参照、必須の節、見出しの要約、記法、Summary のスクリーンショット、base ブランチです。

リリースの種類が nx のリポジトリでは、題の scope が、変更した nx のプロジェクトの scope と違うときも、同じ失敗を返します。

積んだ base の scope は、下の段の PR がマージ済みなら、記録のコミットから head までの差分で求めます。開いている間は、下の段のブランチとの差分で求めます。prepare の目安は、記録のコミットから求めます。

dry_run を付けなければ、セッションのディレクトリを pr_check と同じように確かめます。引っかかりが見つかると、それぞれを warnings に入れ、kind が preflight-failed の失敗を返します。積んだブランチが remote とずれたときの Push Status の直し方も、pr_check と同じに決めます。

dry_run を付けると、検証して、作る予定の head・base・題を結果に入れ、PR は作りません。

dry_run で下の段の PR が開いているときは、スタックへの登録の予定も、結果の stack に入れます。

PR を作った後、head ブランチが指す Issue を In Review にします。テンプレートが release のときは行いません。

project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

ホストの GitHub トークンが要ります。

head ブランチを push 済みにし、作業ツリーの変更を無くしておきます。fork のブランチは、その owner の fork を指す remote に push しておきます。

使用例

PR のテンプレートを書き、そのパスを返します。

{
  "name": "pr_create",
  "arguments": {
    "prepare": true
  }
}

PR を作らずに、ファイルを検証します。

{
  "name": "pr_create",
  "arguments": {
    "file": ".pecot/tmp/output/pr-create-20260101-120000.md",
    "dry_run": true
  }
}

ファイルを使わずに、引数から PR を作ります。

{
  "name": "pr_create",
  "arguments": {
    "message": "<body>",
    "title": "feat: add a report",
    "base": "develop",
    "repo": "example-org/my-repo"
  }
}

検証に失敗したときと、事前の確認が引っかかりを見つけたときは、PR を作りません。PR を作った後でボードの status を設定できないときは、PR は残り、warnings に入れます。prepare が書いたテンプレートのコピーは、.pecot/tmp/output/ に残ります。ボードの status だけを設定できなかったときは、成功を返します。

もし事前の確認が git のリポジトリでないなどの致命的な場合に当たったなら、失敗を返します

PW-PR-CREATE-38

もし develop_branch か release_branch が設定に無いなら、検証の前に、kind が repo-setting-missing の失敗を返します

PW-PR-CREATE-39

もしボードの status を In Review にできなかったなら、warnings に入れます。選択肢の ID が古くて書けないときは、ID を読み直す project_activate の案内を、待っている Issue の書き込みと合わせて 1 回だけ添えます

PW-PR-CREATE-40

もし PR の作成で GitHub API がエラーを返したなら、失敗を返します

PW-PR-CREATE-41

もし対象のリポを含む設定が 2 つ以上あり、アクティブなプロジェクトがそのどれも指さないなら、kind が no-active-project の失敗を返します。detail に候補の名前と project の案内を入れます

PW-PR-CREATE-42

もし template が default でも release でもないなら、kind が invalid-input の失敗を返します

PW-PR-CREATE-43

もし prepare・file・message のどれも渡していないなら、kind が invalid-input の失敗を返します

PW-PR-CREATE-44

もし message に title か base を渡していないなら、kind が invalid-input の失敗を返します

PW-PR-CREATE-45

もし file と一緒に screenshot を渡したなら、kind が invalid-input の失敗を返します

PW-PR-CREATE-46

もしフロントマターを読めないか、repository が owner/repo の形でないなら、kind が content-invalid の失敗を返します

PW-PR-CREATE-47

もし message のリポジトリを決められないか、repo が owner/repo の形でないなら、kind が invalid-input の失敗を返します

PW-PR-CREATE-48

もし head ブランチを決められないなら、kind が git-unresolved の失敗を返します

PW-PR-CREATE-49

積んだ base の記録があるときに prepare を付けて呼ぶと、コピーの base に記録の base（下の段のブランチ）を入れます

PW-PR-CREATE-50

積んだ base の記録があり、下の段の PR が開いているときに呼ぶと、base を下の段のブランチにして PR を作ります

PW-PR-CREATE-51

積んだ base の PR を作ると、下の段のスタックに登録し、結果の stack の registered を true に、number をスタックの番号にします

PW-PR-CREATE-52

積んだ base の記録があり、下の段の PR がマージ済みのときに呼ぶと、base を開発ブランチにして PR を作ります

PW-PR-CREATE-53

記録が無いか、開発ブランチからの着手のときに呼ぶと、今までどおり開発ブランチを base にします

PW-PR-CREATE-54

head の引数かフロントマターの head で別のブランチを指したときと、リリースの PR では、記録を読みません

PW-PR-CREATE-55

PR を作ると、head ブランチの Issue を待っている Issue のうち、選んだプロジェクトのボードに載っているものを読み、列を動かして moves に入れます。判定に作った PR が出ていないときは、約 1.5 秒待ってから 1 回だけ読み直します

PW-PR-CREATE-56

待っている Issue に着手の跡がある間、その Issue の列を動かしません

PW-PR-CREATE-57

もし下の段の PR が開いておらず、マージもされていないなら、PR を作りません。detail を base branch <base> has no open PR で始め、kind が pr-state の失敗を返します

PW-PR-CREATE-58

もし下の段の PR が開いているのに base が開発ブランチなら、kind が content-invalid の失敗を返します

PW-PR-CREATE-59

もし積んだ base の記録の形が誤っているなら、prepare でも投稿でも、kind が content-invalid の失敗を返します

PW-PR-CREATE-60

もしスタックに登録できないなら、could not register stack: <理由> の文を warnings に入れ、PR は残します

PW-PR-CREATE-61

もし待っている Issue を読めないか動かせないなら、接続の失敗でも warnings に入れ、成功と失敗は変えません。選択肢の ID が古くて動かせないときは、ID を読み直す project_activate の案内を、In Review の書き込みと合わせて 1 回だけ添えます

PW-PR-CREATE-62

積んだ base の記録があるときに題の scope を確かめると、下の段の PR がマージ済みなら記録のコミットから head までの差分で、開いている間は下の段のブランチとの差分で求めます。prepare の目安は記録のコミットから求めます

PW-PR-CREATE-63

dry_run を付け、下の段の PR が開いているときに呼ぶと、結果の stack の lower に下の段の PR の番号を入れます

PW-PR-CREATE-65

もし積んだ base の記録のコミットが head の履歴に無いなら、PR を作らずに、kind が git-unresolved の失敗を返します

PW-PR-CREATE-64

もし head の番号の Issue が PR のリポジトリに無いなら、待っている Issue の確認を、何も返さずに飛ばします

PW-PR-CREATE-66

prepare を付けて呼ぶと、作業中の Issue を git remote のリポジトリと今のブランチ名の末尾の番号から求めます

PW-PR-CREATE-67

もし古い版の .pecot-active が残っているなら、その内容を読まずに、ブランチ名から求めた番号を Closes に入れます

PW-PR-CREATE-68

もし .pecot/state/ の無い clone で紐づいたブランチにいるなら、prepare でも Closes にブランチ名の番号を入れます

PW-PR-CREATE-69

もし積んだ記録があり、事前の確認がブランチと remote のずれを見つけたなら、Push Status の直し方を pr_check と同じに決めます

PW-PR-CREATE-70

もし積んだ base の記録のコミットが head の履歴に無く、pr_restack と同じ判断で載せ直し済みと決まったなら、記録の書き直しを detail で案内します。案内するのは pr_restack です。決まらなければ案内しません

PW-PR-CREATE-71

記録が無く、作業中の Issue の判定が stackable で、ブランチが下の段の変更を持つ間、下の段のブランチを base にします。下の段を載せ直して force-push した後も同じです

PW-PR-CREATE-72

記録が無く、作業中の Issue の判定が startable の間、develop_branch を base にします

PW-PR-CREATE-73

もし記録が無く、積んだ先を求められないなら、投稿では detail を cannot infer the stacked base で始めて失敗を返し、PR を作りません

PW-PR-CREATE-74

もし記録が無く、積んだ先を求められないなら、dry_run では warnings に入れ、develop_branch を base にします

PW-PR-CREATE-75

もし対象のリポを含む設定が無いなら、prepare の無いときは、kind が repo-not-in-project の失敗を返します

PW-PR-CREATE-76

project に設定の名前を渡して呼ぶと、対象のリポを含む設定が 2 つ以上あっても、その設定を使います

PW-PR-CREATE-77

message で repo を省いて呼ぶと、origin のリポが設定に無くても、設定にあるリポを指す別の remote のリポに PR を作ります

PW-PR-CREATE-78

もし対象のリポを含む設定が無いなら、prepare では warnings に入れ、テンプレのコピーを書いて成功を返します

PW-PR-CREATE-79

もし作業中の Issue の種類を GitHub から読めないなら、prepare では Closes を空のままにし、warnings に入れて、テンプレのコピーを書きます

PW-PR-CREATE-80

owner:branch の head を渡すと、そのブランチが owner の fork を指す remote に push 済みのとき、その head で PR を作ります

PW-PR-CREATE-81

もし owner:branch の head のブランチが fork に無いか、fork とずれているなら、remote とブランチ名を示した直し方を warnings に入れます。PR を作らずに、kind が preflight-failed の失敗を返します

PW-PR-CREATE-82

もし設定のホストに、owner:branch の owner の fork を指す remote が無いなら、git remote add の直し方を warnings に入れます。kind が preflight-failed の失敗を返します

PW-PR-CREATE-83

もし head の owner かブランチ名が空なら、PR を作らずに、kind が invalid-input の失敗を返します

PW-PR-CREATE-84

owner:branch の head を渡すと、ブランチ名の末尾の番号の Closes を本文に足します

PW-PR-CREATE-85

head で今と別のブランチを指すと、PR を作る前に、そのブランチの push を確かめます

PW-PR-CREATE-86

head の owner に作り先のリポの owner を書くと、作り先のリポを指す remote で push を確かめます
