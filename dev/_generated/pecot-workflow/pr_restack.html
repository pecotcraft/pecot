Restack branch

pr_restack

スタックしたブランチを、base にしたブランチの新しい位置へスタックし直します。

今のブランチを、スタックして着手したときの base の記録を使って、親ブランチの新しい位置へスタックし直します。GitHub を読み書きしません。親 PR と今のブランチの PR は、reads に渡した公式の MCP の読み取りの結果から読みます。

check を付けると、スタックし直しが要るかだけを返します。変わるのは、git fetch が進める手元の追跡参照だけです。

スタックしていないブランチ（開発ブランチからの着手の記録か、記録が無いもの）は、スタックし直しません。

スタックしたブランチで reads.pull_requests が無いときは、親ブランチと読み方を detail に入れ、kind が invalid-input の失敗を返します。

スタックし直しが要るのは、親ブランチの remote の先頭が記録の位置と違うときと、親 PR がマージ済みのときです。マージ済みなら開発ブランチへスタックし直し、base の記録を開発ブランチからの着手に変えます。

ブランチが新しい base の上に載り終えていれば、記録が古くても rebase をしません。載り終えているとは、新しい base がブランチの履歴にあり、記録の位置もブランチの履歴にあるなら、それが新しい base の履歴にもあることです。push と記録の書き直しは、check なしの pr_restack が行います。remote のブランチが同じ木で新しい base の上にあれば、push せずに remote のブランチに合わせます。

rebase の後、remote のブランチにだけあるコミットがあれば止まります。push がそのコミットを消すためです。ブランチはスタックし直す前の位置へ戻します。

同じ変更かは、スタックし直す前と後のブランチの両方と比べます。GitHub が書き換えたコミットを、別の変更と見ないためです。

git rebase --no-update-refs --onto <新しい base> <記録の位置> を動かします。

記録の位置がブランチの履歴に無いときは、別の点から rebase を始めます。親ブランチの追跡参照からの fork-point を使い、求まらなければ新しい base との merge-base を使います。親 PR がマージ済みでも同じです。

結果の木が remote のブランチと同じで、remote のブランチが新しい base の上にあれば、remote のブランチに合わせ、push しません。

そうでなければ、fetch した位置を期待の値にした git push --force-with-lease で push します。pre-push のフックを含めて、10 分まで待ちます。remote に無いブランチは push しません。

スタックし直した後、base の記録の位置を、ブランチと新しい base の merge-base に書き直します。

開発ブランチへスタックし直すか合わせた後に、reads.pull_request の PR を見ます。今のブランチの開いている PR で、本文に Closes などのこのリポの Issue があれば、その番号と理由を relink に返します。GitHub は、スタック PR の Closes を Issue とリンクせず、base を付け替えても本文を読み直さないためです。PR は書きません。

relink の reason には、update_pull_request で本文を変えずに保存し直す案内を入れます。PR の base が開発ブランチでなければ、base を開発ブランチにする案内も入れます。

開発ブランチへスタックし直すか合わせた後に reads.pull_request が無いときは、relink を返さず、渡すよう案内する文を warnings に入れます。

衝突したら、衝突したファイルを conflicts に入れ、rebase を途中のまま残します。途中の記録を書き、kind が git-conflict の失敗を返します。

continue は、衝突を解いて git add した後に続けます。abort は、スタックし直す前の位置に戻します。どちらも途中の記録だけを読み、pecot が始めていない rebase は動かしません。

check・continue・abort は、1 つだけ渡せます。

check を付けたときの成功の結果の文は、up to date: <branch> on <base> か needs restack: ... です。

書き換えるのは、セッションのディレクトリのブランチだけです。ほかの worktree には触れません。

project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

スタックして着手した作業ディレクトリで呼びます（session_start が base の記録を書きます）。

使用例

今のブランチにスタックし直しが要るかを確かめます。

{
  "name": "pr_restack",
  "arguments": {
    "check": true
  }
}

今のブランチをスタックし直して push します。

{
  "name": "pr_restack",
  "arguments": {}
}

衝突を解いて git add した後に、続けます。

{
  "name": "pr_restack",
  "arguments": {
    "continue": true
  }
}

スタックし直す前の位置に戻します。

{
  "name": "pr_restack",
  "arguments": {
    "abort": true
  }
}

出力

MCP の結果の項目

項目名

型

説明

branch

string

スタックし直すブランチです。

base

string

スタックし直した後の base のブランチです。親 PR がマージ済みなら、開発ブランチです。

outcome

"up-to-date" | "needs-restack" | "restacked" | "synced" | "conflict" | "aborted"

起きたことです。up-to-date・needs-restack・restacked・synced・conflict・aborted のどれかです。check を付けたときは、スタックし直すと何が起きるかです。

cause

"base-moved" | "base-merged"

スタックし直しが要る理由です。base-moved か base-merged です。check を付けて、スタックし直しが要るときだけ入ります。

pullRequest

integer

マージ済みの親 PR の番号です。cause が base-merged のときだけ入ります。

pushed

boolean

ブランチを push したかどうかです。outcome が restacked のときだけ入ります。

conflicts

array

衝突したファイルの一覧です。outcome が conflict のときだけ入ります。

relink

object

update_pull_request で本文を保存し直す PR です。pullRequest（PR の番号）と reason（書く値と理由）を持ちます。開発ブランチへスタックし直すか合わせた後、reads.pull_request の開いている PR の本文がこのリポの Issue を閉じるときだけ入ります。

エラーと警告の項目については、共通仕様の出力を参照してください。

エラー

エラー名

説明

git-unresolved

ディレクトリが git のリポジトリではありません。git remote が無いときと、今のブランチかリポジトリを決められないときも含みます。

git-unresolved

git fetch が失敗したか、remote に届きません。スタックし直す先のブランチが手元の追跡参照に無いときも含みます。remote のブランチにだけあるコミットがあるときと、push が拒まれたか、時間切れのときも同じです。

no-active-project

対象のリポを含むプロジェクトの設定が 2 つ以上あり、使う設定が決まりません。アクティブなプロジェクトが候補を指さず、project もありません。

repo-not-in-project

対象のリポを含むプロジェクトの設定がありません。project で選んだ設定が対象のリポを含まないときも含みます。

project-not-found

project の名前の設定がありません。

repo-setting-missing

develop_branch が未設定です。

content-invalid

スタックした base の記録か、途中の記録の形が誤っています。

pr-state

親ブランチが remote から消えていて、その PR がマージされていません。

github-mcp-shape

reads に渡した値が、公式の GitHub MCP の list_pull_requests・pull_request_read の結果の形と違います。

preflight-failed

未コミットの変更があります。check・continue・abort では確かめません。

git-conflict

スタックし直しが衝突しました。continue の後に、また衝突したときも含みます。detail が、衝突を解く手順と、continue・abort の呼び出しを案内します。

invalid-input

check・continue・abort を 2 つ以上渡したか、途中のスタックし直しが無いのに continue・abort を渡しました。pecot の記録が無い rebase の途中のときと、スタックしたブランチで reads.pull_requests が無いとき、ほかの引数の誤りも含みます。

project-root-not-found

プロジェクトのルートを決められません。

other

ほかの名前に当たらない失敗です。ツールの想定外の例外も含みます。

session-directory-unresolved

サーバがセッションのディレクトリを決められず、ツールを動かしません。

衝突で止まったときは、rebase は途中のまま残り、base の記録は変わりません。push が拒否・時間切れ・取り消しで止まったときは、手元のブランチはスタックし直した後のままで、base の記録は変わりません。拒まれたか取り消されたときは、同じ引数で呼び直せば続きます。時間切れのときは、手で push してから呼び直すと、remote に合わせて続きます。remote のブランチにだけあるコミットで止まったときは、ブランチをスタックし直す前の位置へ戻します。
