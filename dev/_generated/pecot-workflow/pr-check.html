Check PR readiness

Check PR readiness

pr_check

PR を作る前に確かめる情報を、まとめて出します。

directory のリポジトリについて、PR を作る前に確かめる情報を返します。

結果には、remote・今のブランチ・Push Status・base ブランチ・git status・コミット・差分の統計・worktree・stash の一覧を入れます。

base ブランチは、<remote>/ の後に、選んだプロジェクトの develop_branch を続けたものです。<remote> は remote の origin で、origin が無ければ最初の remote です。

積んで着手した記録があるときは、base ブランチは、<remote>/ の後に下の段のブランチを続けたものです。remote がそのブランチは無いと答えれば（マージで消えた後）、手元に追跡参照が残っていても develop_branch の方にします。remote に届かなければ、手元の追跡参照の有無で決めます。

作業ディレクトリの worktree に .pecot/state/.pecot-base が無いときは、積んだ先を求めます。作業中の Issue の判定が stackable で、判定の示すブランチの変更をブランチが持てば、そのブランチに積んだものとします。変更を持つとは、同じコミットか、そのブランチを載せ直した後の同じ patch を持つことです。そのブランチが自分のコミットを持たなければ、その先頭がブランチの祖先であることです。

そうでなければ、開発ブランチからの着手とします。判定を読めないか blocked のときと、GitHub に届かないとき、追跡参照が無いときは、cannot infer the stacked base の文を warnings に入れます。求めた結果は書きません。

下の段のブランチについての remote への問い合わせには、10 秒の時間切れがあり、認証の入力は求めません（GIT_TERMINAL_PROMPT=0 と askpass の無効化）。時間切れは、remote に届かないときと同じに扱います。

下の段のブランチが remote にあり、手元に追跡参照が無いときは、develop_branch と比べ、git fetch を案内する文を warnings に入れます。この文は、確かめた結果の数に入りません。

積んだ base の記録の形が誤っているときは、base を決められないので、kind が content-invalid の失敗を返します。

確かめた結果に引っかかりがあっても、すべての項目を返します。

引っかかりとして数えるのは、push していないか remote とずれたブランチ、変更したファイルか追跡していないファイル、stash の項目です。

積んで着手した記録があり、ブランチが remote とずれているときは、下の段の PR と remote の先頭を読み、pr_restack と同じに載せ直しの要否を決めます。GitHub を読むのは、このときと、記録が無く積んだ先を求めるときだけです。

Push Status の直し方は、載せ直しが要れば pr_restack、決められなければ check を付けた pr_restack です。下の段のブランチが remote から消え、PR がマージされていないときも、決められないに入ります。

ブランチが新しい base の上に載り終えていて記録だけが古いときも、Push Status の直し方は pr_restack です。push と記録の書き直しを pr_restack が行うためです。

ほかに、ブランチが remote とずれて載せ直しが要らないときは、Push Status の直し方は git pull --rebase です。push 済みのコミットを書き換えたなら git push --force-with-lease です。積んでいないブランチも同じです。git は fast-forward でない push を拒むためです。

引っかかりが 1 件以上あると、それぞれを warnings に入れ、kind が preflight-failed の失敗を返します。失敗の結果にも、集めた項目が入ります。

リポジトリと設定を読むだけで、何も変えません。

project で、使うプロジェクトの設定の名前を渡します。省くと、対象のリポを含む設定を使い、2 つ以上あるときは、そのうちアクティブな設定を使います。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

ローカルのリポジトリに <remote>/<develop_branch> が要ります。<remote> は remote の origin で、origin が無ければ最初の remote です。

使用例

PR を作る前に、セッションのディレクトリのリポジトリを確かめます。

{
  "name": "pr_check",
  "arguments": {
    "directory": "."
  }
}

引数

directory

対象の Git リポジトリのパスです。絶対パスと相対パスのどちらも渡せます。相対パスは、セッションのディレクトリから見たものです。

指定:

必須

型:

string

project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、対象のリポを含む設定を使います。 省くと、対象のリポを含む設定を使います。2 つ以上あるときは、その中のアクティブな設定を使います。

指定:

省略可

型:

string

出力

MCP の結果の項目

項目名

型

説明

remoteUrl

string

主な git remote の URL です。

currentBranch

string

今のブランチです。

pushed

boolean

今のブランチを push 済みで、リモートのブランチと同じかどうかです。

pushStatus

string

Push Status の状態を書いた文です。

baseBranch

string

比べる相手のリモートブランチです。remote/branch の形です。積んでいるときは下の段、そうでなければ develop ブランチです。

gitStatus

string

git status の出力です。

commits

string

ベースブランチからのコミットを、1 行に 1 件ずつ並べた文です。

diffSummary

string

ベースブランチとの差分の統計を書いた文です。

worktree

object

worktree の情報です。list（git worktree list の出力）と directoryName（今のディレクトリの名前）を持ちます。リンクされた worktree かどうかを示す isWorktree は、判定できたときだけ入ります。

stashList

string

stash の一覧を書いた文です。

エラーと警告の項目については、共通仕様の出力を参照してください。

エラー

エラー名

説明

git-unresolved

ディレクトリが git のリポジトリではありません。git remote が無いときと、今のブランチかリポジトリを決められないときも含みます。

no-active-project

対象のリポを含むプロジェクトの設定が 2 つ以上あり、使う設定が決まりません。アクティブなプロジェクトが候補を指さず、project もありません。

repo-not-in-project

対象のリポを含むプロジェクトの設定がありません。project で選んだ設定が対象のリポを含まないときも含みます。

project-not-found

project の名前の設定がありません。

repo-setting-missing

develop_branch が未設定です。

git-unresolved

<remote>/<develop_branch> がありません。<remote> は remote の origin で、origin が無ければ最初の remote です。

content-invalid

積んだ base の記録の形が誤っています。

preflight-failed

warning が 1 件以上あります。

invalid-input

directory が無いか、ほかの引数の誤りがあります。

project-root-not-found

プロジェクトのルートを決められません。

other

ほかの名前に当たらない失敗です。MCP のツールでは、コマンドの想定外の例外も含みます。

session-directory-unresolved

MCP のツールだけで起きます。サーバがセッションのディレクトリを決められず、コマンドを動かしません。
