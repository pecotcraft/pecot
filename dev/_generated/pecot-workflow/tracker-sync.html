Sync Tracker list

tracker_sync

source に選んだものの一覧を、open の Tracker に書き直します。dependabot は人の判断を待つ Dependabot の PR、security は open のセキュリティ alert です。

source で、Tracker に載せるものを選びます。dependabot は人の判断を待つ Dependabot の PR、security は open のセキュリティ alert です。

dependabot では、ラベルが dependabot-pr で、本文に Tracker の印がある open の Tracker の Issue を探します。

dependabot では、Tracker の本文の list-begin と list-end の間にある表を書き直します。

dependabot では、表には、人の判断を待つ open の Dependabot の PR を載せます。

dependabot では、判断を待つ理由の無い PR は載せません。

dependabot では、PR が自動マージの対象になるのは、次の 2 つがそろうときです。最初のコミットの作者が dependabot[bot] で、署名が有効なこと。分かっている update type のうち最大のものが minor か patch であること。

dependabot では、update type が不明の依存は、ほかの依存の type が分かっている間は無視します。PR を不明として数えるのは、どの依存の type も分からないときだけです。

dependabot では、update type が major か不明の PR は載せます。

dependabot では、対象の PR は、検証が失敗していると載せます。

dependabot では、自動マージを入れた対象の PR は、最後の push から 24 時間たっても検証が終わらないと載せます。

dependabot では、対象の PR は、30 分を超えて競合していると載せます。最後の push と base ブランチの最新のコミットのうち、遅い方から数えます。

dependabot では、対象の PR は、最後の push の後で merge queue から外され、自動マージも merge queue の登録も無いと載せます。

dependabot では、自動マージも merge queue の登録も無い対象の PR は、最後の push から 30 分たつと載せます。

dependabot では、最後の push は、最後の force push です。force push が無ければ、PR の作成です。

dependabot では、表の各行は、PR の題、PR へのリンク、検証の状態（passed・failed・pending・none）です。

dependabot では、判断を待つ理由は、Tracker の表にも結果の項目にも入りません。CLI では、結果の行に出します。

dependabot では、open の Tracker が無く、載せる PR があるときは、Tracker を作ってプロジェクトのボードに足します。Status を Backlog、Priority を medium にします。

dependabot では、open の Tracker が無く、載せる PR も無いときは、何も作りません。

dependabot では、一覧が空で open の Tracker があるときは、一覧を none にし、Tracker を completed として閉じます。

dependabot では、閉じない open の Tracker には、Status と Priority が空の間だけ値を入れます。人が変えた値は残ります。

security では、ラベルが security-alert で、本文に Tracker の印がある open の Tracker の Issue を探します。

security では、Tracker の本文の list-begin と list-end の間にある一覧を、open の alert で書き直します。

security では、open の Dependabot alert と secret scanning alert を読みます。code scanning alert は、既定ブランチの open のものを読みます。

security では、Tracker の本文の見出しと表を、alert の種類ごとに分けます。

security では、Priority は、alert の severity から決めます。

security では、secret scanning alert は、必ず high です。

security では、新しい Tracker の Priority は、行の Priority のうち最も高いものです。

security では、code scanning alert と secret scanning alert の行では、題を masked と書きます。

security では、Dependabot の行には advisory の要約を書きます。同じ advisory の Dependabot alert は、1 つの行にまとめます。

security では、機能が無効の種類は、見出しの下に disabled と書き、行を足しません。

security では、code scanning の解析が無いリポジトリは、code scanning alert が無いものとして数えます。

security では、一覧を取れない種類は、前の行を残します。前の行が無かったときは、unavailable と書きます。

security では、取れない種類があるときは、ほかの種類を反映した後で、kind が partial-failure の失敗を返します。

security では、Dependabot alert の 403 と secret scanning の 404 を、無効だと確かめられなければ、取れなかったものとして数えます。

security では、open の Tracker が無く、載せる行があるときは、Tracker を作ってプロジェクトのボードに足します。Status を Backlog、Priority を最も高い行の値にします。

security では、open の Tracker が無く、載せる行も無いときは、何も作りません。

security では、Tracker を閉じることはありません。

security では、alert がすべて無くなると、どの種類も none と書きます。Tracker を閉じて Archived へ動かすのは、人です。

security では、既にある Tracker には、Status と Priority が空の間だけ値を入れます。人が変えた値は残ります。

Tracker の本文のうち、一覧の印の外にある文はそのまま残します。

プロジェクトの設定が定義していないフィールドは設定しません。

open の Tracker が複数あるときは、番号が最小のものを使い、ほかは open のまま残します。

閉じた Tracker は使い回しません。

対象のリポを repositories か aggregation_repo に持つプロジェクトの設定が要ります。2 つ以上あるときは、アクティブなプロジェクトか project で選びます。

ホストの GitHub トークンと、Issue とプロジェクトを編集する権限が要ります。security では、セキュリティ alert を読む権限も要ります。

対象のリポジトリは、引数 repo です。無ければ、セッションのディレクトリ（CLI では作業ディレクトリ）の remote の origin です。origin も無ければ、最初の remote です。

使用例

GitHub へ書き込まず、Tracker を変える予定を返します。

{
  "name": "tracker_sync",
  "arguments": {
    "source": "dependabot",
    "dry_run": true
  }
}

Tracker の一覧を書き直します。必要なら、Tracker を作るか閉じます。

{
  "name": "tracker_sync",
  "arguments": {
    "source": "dependabot"
  }
}

GitHub へ書き込まず、Tracker を変える予定を返します。

{
  "name": "tracker_sync",
  "arguments": {
    "source": "security",
    "dry_run": true
  }
}

Tracker の一覧を書き直します。必要なら、Tracker を作ります。

{
  "name": "tracker_sync",
  "arguments": {
    "source": "security"
  }
}

dependabot では、作った Tracker は、ボードへの配置に失敗しても GitHub に open のまま残り、次の実行でボードに置きます。本文の書き直しに失敗したときは、本文は元のままで、Tracker は open のままです。クローズに失敗したときは、一覧は none のまま、Tracker は open のままで、次の実行で閉じます。security では、作った Tracker は、ボードへの配置に失敗しても GitHub に open のまま残り、次の実行でボードに置きます。本文の書き直しに失敗したときは、本文は元のままで、次の実行でやり直します。どちらも、済んだ変更は巻き戻さず、kind が partial-failure の失敗を返します。この失敗の結果にも、済んだ変更の tracker・created・added・removed・closed が入ります。

コマンド

GitHub Actions からは、pecot tracker sync コマンドで呼びます。引数は、次のフラグで渡します。

pecot tracker sync <source> [options]
<source>

引数 source に当たります。

--dry-run

引数 dry_run に当たります。

--project

引数 project に当たります。

GitHub へ書き込まず、Tracker を変える予定を出します。

pecot tracker sync dependabot --dry-run

Tracker の一覧を書き直します。必要なら、Tracker を作るか閉じます。

pecot tracker sync dependabot

GitHub へ書き込まず、Tracker を変える予定を出します。

pecot tracker sync security --dry-run

Tracker の一覧を書き直します。必要なら、Tracker を作ります。

pecot tracker sync security

標準出力には何も出しません。

  • 標準エラー: dependabot では、count の行で、open の Dependabot の PR の数、判断を待つ PR の数、判断を待つ PR のうち検証の結果が無いものの数を出します。変更ごとに結果の行（created・added・removed・updated・unchanged・closed・skipped）を出します。--dry-run のときは、代わりに dry-run の行を出します。open の Tracker が複数あるときは、warning の行を出します。失敗ごとに error の行を出します。security では、変更ごとに結果の行（created・added・removed・updated・unchanged・skipped）を出します。--dry-run のときは、代わりに dry-run の行を出します。open の Tracker が複数あるときは、warning の行を出します。失敗ごとに error の行を出します。一覧を取れなかった種類ごとの行も含みます。
