auto start

auto start

自動処理の実行を始めます。自動処理が書いた Status を戻し、続きに要る文脈を JSON のファイルに書きます。

自動処理の job が、AI の step の前に呼びます。文脈の JSON を、RUNNER_TEMP の下の pecot-auto/context.json に書きます。欄は、Issue・計画・前回までの結果・答え・本文を書かなかったコメントの数・ブランチ・PR です。

書いたファイルのパスを、outputs の context-file に出します。ワークフローは、このパスをスキルへのプロンプトで渡します。

計画は、見出し ## Plan で始まるコメントのうち、bot か書き込み権限を持つ人が書いた最後のものです。

答えは、最後の結果のコメントの後に付いたコメントのうち、書いた人の権限が admin か write のものです。

ほかの人の計画と答えは、本文を書かずに数だけを書きます。

Issue がボードに無ければ、進行の欄を Ready にしてボードに載せます。

既定の Status が、自動処理の書いた Needs Attention なら、開いた PR があれば In Progress に、無ければ Todo に戻します。pecot の判定が置いた Needs Attention は戻しません。

どちらでもなければ、ボードに何も書きません。

Issue にブランチと開いた PR のどちらも無ければ、AI の step の前に、Issue につないだブランチ feat/auto/<番号> を作り、文脈の branch にその名前を入れます。

作るブランチの元は、着手の判定がスタック先を選んだときはそのブランチで、そうでなければ設定の develop_branch です。前提が済んでいない Issue と、develop_branch が無いリポでは、ブランチを作らずに step を失敗にします。

プロジェクトの設定に fields.status が要ります。

リポジトリを checkout した後の step で呼びます。

対象のリポを含み、fields.status を持つプロジェクトの設定が要ります。

プロジェクトを編集する権限を持つ GitHub トークンが要ります。

使用例

Status を戻し、続きに要る文脈をファイルに書きます。

- uses: pecotcraft/pecot/actions/auto-start@<ref>
  with:
    token: ${{ steps.app-token.outputs.token }}
    issue: ${{ needs.gate.outputs.number }}

入力

issue

Issue の参照です。ワークフローのリポジトリの Issue の番号か、owner/repo/N で渡します。 番号だけの形は、GITHUB_REPOSITORY のリポジトリで補います。

指定:

必須

型:

string

project

.pecot/config/projects の下にある、プロジェクトの設定の名前です。.json を付けずに渡します。省くと、Issue のリポジトリを含む設定を使います。

指定:

省略可

型:

string

token

Issue を読み、ボードを書く GitHub トークンです。ワークフローの App のトークンを渡します。

指定:

省略可

型:

string

出力

outputs の context-file は、文脈を書いた JSON のファイルのパスです。ファイルの欄は、issue（ref・title・body）・plan・results・answers（author・body）・withheld・branch・base・pr です。計画が無いときは空、PR が無いときは 0 です。branch は、Issue のブランチです。無ければ、作ったブランチの名前になります。base は、作ったブランチの元のブランチです。既にあるブランチでは、開発ブランチになります。

  • 標準エラー: 実行のログに、ボードに載せたときは added の行を、Status を戻したときは set の行を出します。ブランチを作ったときは created の行を出します。本文を書かなかったコメントがあるときは、その数を count の行で出します。

action の outputs

名前

説明

context-file

Path of the JSON file with the Issue, the plan, the earlier results, the answers, the branch and the PR, under RUNNER_TEMP

エラー

エラー名

説明

invalid-input

RUNNER_TEMP がありません。step は失敗になります。

invalid-input

issue の形が誤っています。step は失敗になります。

not-initialized

プロジェクトの設定に fields.status がありません。step は失敗になります。

status-not-configured

設定に、要る選択肢がありません。ボードに載せるときは進行の欄の Ready が、Status を戻すときは Todo か In Progress が要ります。step は失敗になります。

not-ready

ブランチを作る Issue の前提が済んでいません。ブランチは作りません。step は失敗になります。

dependency-unreadable

ブランチを作る前の、着手の判定を読めません。step は失敗になります。

repo-setting-missing

ブランチを作るのに、設定のリポジトリに develop_branch がありません。step は失敗になります。

no-active-project

対象のリポを含むプロジェクトの設定が 2 つ以上あり、使う設定が決まりません。アクティブなプロジェクトが候補を指さず、project もありません。step は失敗になります。

project-not-found

project の名前の設定がありません。step は失敗になります。

repo-not-in-project

リポジトリがプロジェクトにありません。step は失敗になります。

github-auth

GitHub トークンが見つからないか、GitHub がトークンを拒みました。step は失敗になります。

github-not-found

GitHub に対象が見つかりません。step は失敗になります。

github-rate-limit

GitHub API のレート制限に当たりました。step は失敗になります。

github-api

GitHub API がほかのエラーを返しました。step は失敗になります。

project-root-not-found

プロジェクトのルートを決められません。step は失敗になります。

other

ほかの名前に当たらない失敗です。step は失敗になります。

ボードへ書く前に止まったときは、何も書きません。step が失敗すると、後の auto-finish が start-outcome を見て setup-missing の結果のコメントを書きます。呼び直せば、同じ判定でボードに載せるか、Status を戻します。

テスト
